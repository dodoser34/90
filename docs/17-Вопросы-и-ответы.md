# 17. Частые вопросы и короткие ответы

Эта глава помогает быстро разобраться в магазине и объяснить проект. Для выполнения действий переходите в указанную главу: там есть шаги и ожидаемый результат. Незнакомые слова — в [словаре](18-Словарь.md).

## Работа с магазином

### Можно читать документацию без Visual Studio Code?

Да. Готовое руководство в Word открывается отдельно от проекта, в том числе на телефоне. Редактор кода нужен только для изменения исходных файлов сайта. Работать с товарами и заказами можно в обычном браузере через админ-панель.

### Чем демо отличается от рабочего магазина?

Демо хранит примерные данные в вашем браузере, имитирует письма и оплату. В рабочем режиме API сохраняет общие товары, пользователей и заказы в базе на сервере. Проверка демо не подтверждает работу настоящей почты и оплаты. [Глава 15](15-Демо-версия.md).

### Почему изменённый товар не появился у другого человека?

Проверьте адрес сайта и режим. В демо и в режиме без API изменения локальны для браузера. В серверном режиме проверьте, что товар сохранён, выбран вариант «На сайте», а другая страница обновлена. [Главы 2](02-Как-запустить.md) и [11](11-Админ-панель.md).

### Для чего покупателю нужна регистрация?

Каталог, товары, отзывы и корзина доступны гостю. Для оформления заказа, кабинета и написания отзыва нужен вход. В рабочем режиме регистрация подтверждается кодом из письма, затем вход выполняется по почте и паролю. Вход через Google и вход только по коду не реализованы.

### Почему письмо с кодом не приходит?

В демо письма не отправляются. При локальном API с исходными настройками код печатается в журнал сервера. На рабочем сайте нужны правильно настроенные SMTP и отправитель; проверьте также «Спам». Если код истёк, запросите новый после установленной паузы. [Главы 2](02-Как-запустить.md) и [13](13-Публикация-на-сервере.md).

### Как войти администратором?

На рабочем сайте используйте доступы, заданные при настройке сервера. У локального API и отдельного демо разные исходные пароли. Все варианты входа собраны в начале [главы 11](11-Админ-панель.md).

### Можно поменять все тексты в админ-панели?

В панели меняются товары, категории, заказы, отзывы, пользователи и шесть фото «О нас». Надписи интерфейса, контакты и оформление меняются в файлах. [Глава 12](12-Тексты-фото-и-частые-правки.md).

### Где хранится корзина?

В браузере покупателя, в `localStorage`. Корзина переживает обычное закрытие вкладки, но не обязана появляться в другом браузере или на другом устройстве. На сервер её содержимое передаётся при оформлении заказа.

### Что происходит, если товара не хватает?

API заново проверяет наличие. Недоступные позиции пропускаются, количество ограничивается остатком. Если доступных товаров не осталось, заказ не создаётся. Поэтому после оформления проверьте итоговый состав. PostgreSQL блокирует изменяемые строки во время оформления, чтобы согласовать одновременные покупки; локальная SQLite не проверяет все те же гарантии.

### Можно изменить цену заказа через браузер?

API берёт цены из своей базы и считает доставку по своим настройкам. Переданные покупателем поддельные суммы не задают стоимость заказа. После оформления в заказе сохраняется состав и цена на тот момент. [Главы 8](08-База-данных.md) и [24](24-API-и-форматы-данных.md).

### Как принимается перевод на Kaspi?

После заказа покупатель видит реквизиты и сумму. Владелец проверяет поступление в банке и вручную отмечает «Оплачен» в панели. Это отличается от автоматического подтверждения банковским сервисом. [Глава 10](10-Оплата.md).

### Тестовая карта действительно снимает деньги?

Нет. `test_card` и `test_kaspi` — имитация. Успешная проверка может поставить заказу отметку «Оплачен», хотя настоящего платежа нет. Перед открытием магазина эти способы убирают из настроек. Для проверки используют только тестовые реквизиты из [главы 10](10-Оплата.md).

### Достаточно включить `kaspi_pay`, чтобы заработала онлайн-оплата?

Нет. В проекте есть адаптер — код связи с провайдером. Перед включением нужно подтвердить доступ к API, проверить реальные адреса, поля запросов, подпись уведомлений и все результаты платежа в среде провайдера. Наличие заполненных ключей само по себе не доказывает готовность подключения.

### Отмена заказа возвращает деньги?

Отмена возвращает товар в остаток и меняет состояние записи. Банковский возврат сама панель не выполняет. Удаление заказа также не заменяет отмену: удаление не возвращает товар на склад. [Глава 11](11-Админ-панель.md).

### Экспорт JSON — полноценная резервная копия?

Нет. Он выгружает часть данных, но не аккаунты и не сами загруженные фото. Для восстановления нужна пара базы `.dump` и фотографий `.tgz`, версия кода и сохранённые настройки. Копии следует хранить вне сервера. [Глава 14](14-Запуск-за-час.md).

### Можно разместить рабочий магазин на GitHub Pages?

GitHub Pages в этом проекте используется для демо. API и PostgreSQL там не запускаются. Для рабочего магазина предусмотрены VPS с Docker либо Render. [Глава 13](13-Публикация-на-сервере.md).

## Как объяснить устройство проекта

### Из каких частей состоит проект?

HTML задаёт содержимое страниц, CSS — оформление, JavaScript — действия в браузере. Python и FastAPI обрабатывают запросы на сервере. PostgreSQL хранит рабочие данные. Браузер и сервер обмениваются запросами через API. [Глава 3](03-Устройство-проекта.md).

### Почему здесь нет React или Vue?

Текущий интерфейс написан на обычном JavaScript. Файл `app.js` подключает модули, `App.db` даёт общий способ работы с данными, повторяемые части интерфейса вынесены в компоненты. Это выбор реализации проекта, а не гарантия большей скорости любого сайта. [Глава 6](06-Фронтенд-JavaScript.md).

### Что делает FastAPI?

Это библиотека для серверного приложения на Python. Она связывает адрес запроса с обработчиком и проверяет входящие данные по схемам. Справочник API доступен по `/api/docs`, только когда включён `DOCS_ENABLED`; в рабочем режиме он обычно выключен. [Глава 7](07-Бэкенд-Python.md).

### Для чего SQLAlchemy и Alembic?

SQLAlchemy помогает читать и менять базу из Python. Alembic хранит последовательность изменений структуры таблиц — миграции. Контейнер API применяет их при запуске. Обратная миграция не заменяет резервную копию и не обязана вернуть удалённые данные. [Глава 8](08-База-данных.md).

### Как хранятся пароль и вход пользователя?

В серверной базе хранится хеш пароля, а не исходный пароль. После входа браузер получает случайный токен и передаёт его с запросами. В базе хранится отпечаток токена; выход и блокировка позволяют прекратить доступ. Демо использует упрощённое локальное хранение и не является образцом защиты рабочего магазина. [Глава 9](09-Безопасность.md).

### Кто решает, что пользователь — администратор?

API проверяет сессию и роль при каждом закрытом запросе. Отсутствие кнопки или скрытая ссылка сами по себе не защищают данные. Рабочего администратора задают серверными настройками; покупатель не может назначить себе роль в запросе.

### Какие меры защиты предусмотрены?

Проверка входных данных, параметризованные запросы к базе, безопасный вывод текста, ограничения ссылок и загрузок, HTTPS, защитные заголовки и ограничения частоты запросов. Эти меры уменьшают определённые риски, но не доказывают отсутствие всех уязвимостей. Ограничение запросов не заменяет внешнюю защиту от крупной распределённой перегрузки. [Глава 9](09-Безопасность.md).

### Почему интерфейс подходит для телефона?

CSS содержит отдельные правила для разных размеров экрана: меню и фильтры перестраиваются, элементы располагаются удобнее для узкого экрана. Фактический результат проверяют на нужных страницах и устройствах. [Глава 5](05-Фронтенд-CSS-оформление-и-адаптивность.md).

### Что сделано для скорости и качества?

При публикации стили объединяются, Nginx сжимает и кеширует подходящие файлы, начальные данные загружаются через `/api/bootstrap`. Есть отдельные тесты логики, API и сборок. Скорость и корректность конкретной версии подтверждаются измерением и проверкой, а не списком технологий. [Глава 16](16-Тесты-и-проверка-качества.md).

### Что ещё можно добавить?

Например, проверенную онлайн-оплату, уведомления владельцу о заказе, аналитику, казахский язык, внешнее хранилище фотографий. Это направления дальнейшей разработки, а не уже работающие возможности. Уведомления в Telegram и готовая банковская интеграция не следует обещать без отдельного подключения.

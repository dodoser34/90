# 13. Опубликовать магазин в интернете

Публикация — размещение сайта на постоянно работающем сервере. После неё покупатели открывают магазин по общему адресу, а товары, аккаунты и заказы сохраняются в общей базе.

Для первого запуска пригодится человек, который умеет подключаться к серверу и настраивать домен. Владельцу важно подготовить контакты, реквизиты, каталог и проверить результат по [главе 14](14-Запуск-за-час.md).

## Выбрать вариант размещения

| Вариант | Для чего подходит |
|---|---|
| VPS с Docker | Рабочий магазин на своём арендованном сервере; основной сценарий этой главы |
| Render | Рабочий магазин на управляемом хостинге; настройки задаются в его панели |
| GitHub Pages | Демонстрация без общей базы, настоящих писем и оплаты |
| Свой компьютер | Подготовка и проверка; запуск описан в главе 2 |

VPS — арендованный компьютер в интернете. Docker запускает программы проекта в отдельных окружениях, которые здесь называются контейнерами. Команды ниже относятся к Ubuntu на VPS. Их вводят в терминале после подключения к серверу по SSH, а не в PowerShell своего компьютера.

## Что подготовить для VPS

- Сервер с Docker Engine и Compose v2, Git и Python 3.11 или новее. Ориентир для начала — 2 ГБ оперативной памяти; нагрузка и объём каталога влияют на требования.
- Домен магазина. В его DNS, то есть настройках привязки имени к серверу, основной домен и `www` должны указывать на VPS. Неверные IPv6-записи тоже могут мешать открытию сайта.
- Открытые входящие порты 80 и 443 для сайта. PostgreSQL наружу открывать не нужно.
- Почту с рабочими настройками SMTP — отправки писем приложением. У хостера должна быть разрешена исходящая отправка на нужный почтовый порт.
- Доступ к репозиторию проекта и отдельное место для копий базы и фотографий вне VPS.

Программы устанавливайте по инструкции поставщика сервера и Docker. Не продолжайте запуск, пока `docker compose version`, `git --version` и `python3 --version` не выполняются без ошибки.

## Шаг 1. Получить проект и настройки

В терминале VPS замените адрес репозитория своим:

```bash
git clone https://github.com/ВАШ-ЛОГИН/ВАШ-РЕПОЗИТОРИЙ.git shop
cd shop
umask 077
cp deploy/.env.example deploy/.env
nano deploy/.env
```

Все дальнейшие команды этой главы выполняются из папки `shop`, где находятся `backend`, `frontend` и `deploy`. Файл `.env` — обычный текст с настройками вида `ИМЯ=значение`. Он содержит секреты, поэтому не публикуйте его и не отправляйте в переписке.

Заполните следующие группы. Полное описание каждой переменной — [глава 23](23-Переменные-окружения.md).

| Настройки | Что нужно |
|---|---|
| `DOMAIN`, `LETSENCRYPT_EMAIL` | Домен без `https://` и `www`; почта для уведомлений о сертификате |
| `SECRET_KEY` | Случайный секрет длиной не менее 32 символов |
| `POSTGRES_PASSWORD` | Уникальный пароль базы; для этого шаблона удобно использовать только латинские буквы и цифры, от 24 символов |
| `ADMIN_EMAIL`, `ADMIN_NAME` | Настоящие почта и имя администратора |
| `ADMIN_PASSWORD` или `ADMIN_PASSWORD_HASH` | Пароль администратора от 12 символов либо его хеш — проверочное представление пароля |
| `SMTP_*` | Сервер, порт, логин, пароль и отправитель писем; значения даёт почтовый сервис |
| `PAYMENT_METHODS` | Способы оплаты, которые действительно готовы принимать заказы |
| `KASPI_PHONE`, `KASPI_RECEIVER` | Настоящие реквизиты при включённом `kaspi_transfer` |
| `FREE_SHIPPING_FROM`, `COURIER_PRICE` | Условия курьерской доставки; согласуйте с видимыми текстами сайта |
| `BACKUP_KEEP_DAYS` | Срок хранения локальных копий; в образце 14 дней |

Для генерации `SECRET_KEY` выполните на сервере и перенесите результат в `.env`:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

В образце включены `test_card` и `test_kaspi`. Это имитация оплаты без списания денег. Для реальных покупателей удалите их из `PAYMENT_METHODS`. Например, `PAYMENT_METHODS=cash` оставляет оплату при получении. Для `kaspi_transfer,cash` сначала заполните реальные реквизиты. Включение `kaspi_pay` требует отдельной проверки договора и технического подключения; наличие кода не подтверждает готовность банковского сервиса. См. [главу 10](10-Оплата.md).

Если используете Gmail, проверьте возможность создания пароля приложения в настройках аккаунта Google. Обычный пароль почты не заменяет параметры, которые требует её SMTP-сервис.

## Шаг 2. Подготовить публичные файлы и проверить настройки

```bash
python3 deploy/prepare_frontend.py
docker compose --env-file deploy/.env -f deploy/docker-compose.yml config --quiet
docker compose --env-file deploy/.env -f deploy/docker-compose.yml build backend
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps backend python -m app.cli check
```

**Ожидаемый результат:** сборка создаёт `.public/`, а проверки завершаются без ошибок. Если указано незаполненное поле, исправьте его в `.env` и повторите проверку. Обычный `docker compose config` может напечатать секреты; используйте показанный вариант `--quiet`.

Репозиторий остаётся на сервере для сборки и обновлений. Посетителям Nginx отдаёт только содержимое `.public/` и загруженные фото, а не документацию или исходники сервера.

## Шаг 3. Включить HTTPS и запустить программы

HTTPS шифрует соединение с сайтом. Первая команда получает сертификат для домена и `www`; в этот момент порт 80 должен быть свободен:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml --profile init run --rm --service-ports certbot-init
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec web nginx -t
```

При запуске API проверяет настройки и обновляет структуру базы. Дождитесь готовности `backend`. Если контейнер постоянно перезапускается, прочитайте причину:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml logs --tail=100 backend
```

После успешного запуска добавьте стартовые категории:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec backend python -m app.cli seed --frontend /frontend
```

Эта команда добавляет категории, а не демо-товары. Реальные товары загрузите через админ-панель.

**Результат:** сайт открывается по `https://ВАШ-ДОМЕН`, панель — по адресу `/admin/index.html`. Теперь выполните проверку письма, заказа и резервных копий по главе 14. Открывающейся главной страницы недостаточно для готовности магазина.

В обычном режиме работают пять сервисов: `db` хранит базу; `backend` обрабатывает действия; `web` отдаёт сайт; `certbot` продлевает сертификат; `backup` копирует базу и фото. `certbot-init` нужен отдельно для первоначального выпуска сертификата.

## Обновить сайт или пароль администратора

Перед обновлением сохраните рабочий коммит и резервную пару из главы 14. Затем из корня проекта на VPS:

```bash
git pull
python3 deploy/prepare_frontend.py
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
```

Для изменения только настроек API отредактируйте `.env` и выполните:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d backend
```

При следующем запуске аккаунт администратора получает пароль из настроек. Чтобы хранить его хеш вместо открытого пароля:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps backend python -m app.cli hash-password
```

Перенесите полученную строку в `ADMIN_PASSWORD_HASH` в одинарных кавычках, очистите `ADMIN_PASSWORD` и пересоздайте API командой выше. Сохраните сам пароль в менеджере паролей.

## Если выбран Render

Команды Docker из этой главы к панели Render не относятся. Файл `render.yaml` описывает API, PostgreSQL, постоянный диск фотографий и статический сайт.

1. Подключите репозиторий через создание Blueprint в Render. До подтверждения проверьте предложенные тарифы, диск, хранение данных и копий в панели сервиса.
2. В настройках `kbch-api` заполните адреса `FRONTEND_URL`, `PUBLIC_API_URL` с окончанием `/api`, `CORS_ORIGINS`, администратора, SMTP и реальные способы оплаты. Удалите тестовую оплату перед настоящими продажами.
3. В `kbch-site` задайте `API_URL` — полный адрес API с `/api`, затем запустите повторную публикацию.
4. В админ-панели создайте категории и товары. Выполните проверки из главы 14.

Для фотографий нужен постоянный диск: временные файлы могут исчезнуть при перезапуске. Настройку копий и восстановления на Render проверяют отдельно; контейнер `backup` из Docker Compose там автоматически не запускается.

## Если нужен только показ проекта

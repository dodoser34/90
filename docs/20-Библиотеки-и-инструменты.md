# 20. Библиотеки и инструменты

Эта глава нужна, если вы устанавливаете проект, обновляете его или разбираетесь в ошибке зависимостей. Для повседневной работы в админке её можно пропустить. Ниже указаны версии из файлов проекта; это не список самых новых выпусков.

**Библиотека** — готовый код для определённой задачи. **Фреймворк** даёт основу приложения. **Драйвер** помогает работать с базой. **Инструмент** запускается отдельной командой. Всё, без чего программа не сможет выполнить свои задачи, называют её **зависимостями**.

## Что устанавливается для сервера

Основной список находится в `backend/requirements.txt`. Запись `==` означает, что устанавливается именно указанная версия.

| Библиотека | Версия | Для чего нужна |
|---|---|---|
| FastAPI | `0.143.1` | Принимает запросы по адресам API, проверяет поля и формирует схему API |
| Starlette | `1.8.0` | Помогает FastAPI обрабатывать HTTP, общие проверки запросов и раздачу файлов |
| Uvicorn с дополнениями `standard` | `0.32.1` | Запускает Python API и принимает подключения |
| Gunicorn | `23.0.0` | Управляет несколькими процессами API в Linux |
| SQLAlchemy с дополнениями `asyncio` | `2.0.36` | Описывает таблицы и выполняет запросы к базе |
| asyncpg | `0.30.0` | Соединяет приложение с PostgreSQL |
| aiosqlite | `0.20.0` | Соединяет приложение с локальной SQLite |
| Alembic | `1.14.0` | Применяет последовательные изменения структуры базы |
| pydantic-settings | `2.6.1` | Читает настройки окружения и `.env` |
| email-validator | `2.2.0` | Проверяет правильность формата почтового адреса |
| bcrypt | `4.2.1` | Создаёт и проверяет защищённые отпечатки паролей |
| httpx | `0.28.1` | Отправляет HTTP-запросы платёжному сервису и используется в тестах |
| aiosmtplib | `3.0.2` | Отправляет письма через SMTP |

Дополнения в квадратных скобках, например `uvicorn[standard]`, просят установить ещё несколько нужных пакетов вместе с основной библиотекой.

`backend/requirements-dev.txt` сначала подключает основной список строкой `-r requirements.txt`, затем добавляет инструменты проверки:

| Инструмент | Версия | Для чего нужен |
|---|---|---|
| pytest | `8.3.4` | Находит и запускает Python-тесты |
| pytest-asyncio | `0.24.0` | Позволяет тестировать действия с `async` и `await` |

Pydantic проверяет входящие поля API. Он используется в коде напрямую, но отдельной строки `pydantic==…` в списке нет: его устанавливают другие зависимости. Так же устанавливаются вспомогательные пакеты остальных библиотек. Полного файла с зафиксированными версиями всех таких пакетов в проекте нет. Две установки в разное время могут получить разные вспомогательные версии.

## Как установить и проверить библиотеки

В Windows откройте PowerShell в корне проекта:

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-dev.txt
backend/.venv/Scripts/python.exe -m pip check
```

Первая команда создаёт отдельную папку Python для этого проекта. Вторая устанавливает библиотеки. Третья проверяет, не конфликтуют ли их требования. Если всё совместимо, последняя команда выводит `No broken requirements found.`. Проверка совместимости пакетов не заменяет запуск тестов магазина.

На Linux и macOS вместо `backend/.venv/Scripts/python.exe` используется `backend/.venv/bin/python`. Если вы вызываете Python по этому пути, отдельно активировать окружение не нужно. При сборке Docker-образа основной список библиотек устанавливается автоматически.

Посмотреть фактически установленные версии, Windows:

```powershell
backend/.venv/Scripts/python.exe -m pip show fastapi starlette pydantic
```

Команда `pip freeze`, запущенная через тот же Python, выводит весь список конкретного окружения. Этот список полезен при поиске различий между компьютерами, но сам по себе не доказывает совместимость обновлений.

## Что уже входит в Python

Следующие модули устанавливать через `pip` не нужно:

| Модули | Как используются |

| `pathlib`, `os`, `shutil`, `tempfile` | Пути, файлы, копирование и временные папки сборки |
| `json`, `re`, `urllib.parse` | Чтение данных, поиск по шаблону и разбор адресов |
| `asyncio`, `contextlib` | Ожидание операций и корректное открытие/закрытие ресурсов |
| `secrets`, `hashlib`, `hmac` | Случайные ключи, отпечатки и подписи |
| `datetime`, `time`, `collections` | Даты, сроки кодов и учёт частоты запросов |
| `logging`, `argparse`, `getpass`, `sys` | Журналы, служебные команды и скрытый ввод пароля |
| `http.server`, `functools`, `importlib.util` | Локальная раздача сайта и повторное использование кода |
| `ssl` | Защищённое соединение с базой |

## Что нужно браузеру

Фронтенд не требует `npm install`. В проекте нет `package.json`, React, Vue, Bootstrap, Tailwind, Vite или Webpack. Кнопки, формы, карусели и иконки реализованы собственными файлами. Браузер использует встроенные возможности:

| Возможность | Применение |
|---|---|
| DOM и события | Показ карточек и реакция на действия |
| Fetch API | Запросы к Python API |
| localStorage | Корзина, избранное, данные входа и локальные копии данных |
| URLSearchParams | Параметры поиска и фильтров в адресе |
| Intl | Форматирование чисел и других значений |
| IntersectionObserver | Реакция на появление блока при прокрутке |
| Canvas и работа с изображениями | Подготовка фото в админке |
| CSS Grid, Flexbox, `@media` | Сетки и оформление под разные экраны |

Шрифты Cormorant Garamond, Manrope и Caveat подключаются из Google Fonts ссылками в HTML. Если они не загрузятся, браузер возьмёт резервный шрифт из CSS. Иконки в `frontend/js/core/icons.js` и значок сайта — SVG; отдельная библиотека иконок не устанавливается.

| Инструмент | Значение в проекте | Назначение |

| Docker и Compose v2 | Файлы `backend/Dockerfile` и `deploy/docker-compose.yml` | Упаковывают и запускают сервисы вместе |

## Как обновлять зависимости

1. Измените нужную версию в requirements.
2. Установите её в отдельное окружение и выполните `pip check`.
3. Запустите серверные тесты с SQLite и PostgreSQL, а при изменении работы базы — проверки миграций. Команды есть в [главе 16](16-Тесты-и-проверка-качества.md).
4. Проверьте в браузере затронутые действия. Если менялся JavaScript, выполните его тесты.
5. Заново соберите Docker-образ перед публикацией серверного обновления.

В текущих автоматических проверках нет отдельной проверки стиля Python, TypeScript, npm-сборки и отчёта покрытия тестами. Наличие папок кеша в `.gitignore` не означает, что соответствующий инструмент настроен.

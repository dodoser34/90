# 13. Публикация на сервере

| Где запускаем | Файл настроек | Подробно |
|---|---|---|
| Свой компьютер | **не нужен** | [раздел 2](02-Как-запустить.md) |
| Свой сервер (VPS) с Docker — **рекомендуется** | **`deploy/.env`** (образец `deploy/.env.example`) | этот раздел, вариант 1 |
| Render (без своего сервера) | панель Render → Environment | вариант 2 |
| GitHub Pages (только демо) | не нужен | вариант 3 |

Пароли живут **только** в `deploy/.env` на сервере (или в панели Render): в git, ответы API и журналы они не попадают.
Если что-то заполнено небезопасно, **сервер не запустится** и напишет в журнале, что исправить.
Пошаговый план первого запуска с проверками и откатом — [раздел 14](14-Запуск-за-час.md).

## Основные настройки `deploy/.env`

Полный список полей API, приоритеты и дополнительные переменные — [23](23-Переменные-окружения.md). Устройство сборки, контейнеров, кеша и обновлений — [25](25-Сборка-деплой-и-сопровождение.md).

| Настройка | Что указать | Обязательно |
|---|---|---|
| `DOMAIN` | домен без `https://` и `www`: `kbeauty-chealth.kz` | да |
| `LETSENCRYPT_EMAIL` | почта для писем об HTTPS-сертификате | да |
| `SECRET_KEY` | случайная строка ≥ 32 символов: `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` | да |
| `POSTGRES_DB`, `POSTGRES_USER` | имя базы и пользователя (можно оставить `kbch`) | — |
| `POSTGRES_PASSWORD` | пароль базы: латиница и цифры, 24+ символов | да |
| `BACKUP_KEEP_DAYS` | сколько дней хранить копии (14) | — |
| `ADMIN_EMAIL`, `ADMIN_NAME` | почта и имя администратора | да |
| `ADMIN_PASSWORD` **или** `ADMIN_PASSWORD_HASH` | пароль (≥ 12 символов) или его хеш | да |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_TLS` | почта для писем с кодами (Gmail: `SMTP_PASSWORD` — «пароль приложения») | да |
| `ALLOWED_EMAIL_DOMAINS` | с каких почт можно регистрироваться (пусто — с любых) | — |
| `PAYMENT_METHODS` | способы оплаты через запятую ([раздел 10](10-Оплата.md)) | да |
| `KASPI_PHONE`, `KASPI_RECEIVER`, `KASPI_PAY_LINK` | реквизиты для перевода на Kaspi | для `kaspi_transfer` |
| `KASPI_API_URL`, `KASPI_MERCHANT_ID`, `KASPI_API_KEY`, `KASPI_WEBHOOK_SECRET` | ключи Kaspi Pay | для `kaspi_pay` |
| `FREE_SHIPPING_FROM`, `COURIER_PRICE` | бесплатная доставка от суммы и цена курьера, ₸ | — |
| `SESSION_DAYS` | сколько дней действует вход (30) | — |
| `RATE_*` | лимиты попыток ([раздел 9](09-Безопасность.md)) | — |
| `WEB_CONCURRENCY` | число процессов API (≈ ядра процессора) | — |
| `DOCS_ENABLED` | показывать `/api/docs` (по умолчанию нет) | — |

Адреса сайта и API, рабочий режим, подключение к базе и доверие к Nginx `docker-compose.yml` вычисляет сам из `DOMAIN` и пароля базы.

## Вариант 1. Свой сервер (VPS) с Docker

На одном сервере работают пять программ («контейнеров»):

| Контейнер | Что делает |
|---|---|
| `db` | База PostgreSQL 16 во **внутренней сети** — из интернета недоступна; данные в томе `pgdata` |
| `backend` | API на Python; при запуске проверяет настройки и применяет миграции базы |
| `web` | Nginx: отдаёт сайт из `.public/`, передаёт `/api` в API, раздаёт фото, включает HTTPS и лимиты |
| `certbot` | Продлевает HTTPS-сертификат Let's Encrypt (бесплатный, на 90 дней) |
| `backup` | Раз в сутки — копия базы и фото в `deploy/backups/` |

**Что нужно:** VPS с Ubuntu (от 2 ГБ памяти), Docker с Compose v2, Git, Python 3.11+; домен и `www`, направленные на IP сервера;
открытые порты 80 и 443; разрешённая хостером исходящая почта (SMTP 587).

```bash
curl -fsSL https://get.docker.com | sh
```
```bash
git clone https://github.com/<логин>/<репозиторий>.git shop && cd shop
```
```bash
umask 077 && cp deploy/.env.example deploy/.env && nano deploy/.env
```
Заполните строки «← ОБЯЗАТЕЛЬНО». Затем:

```bash
python3 deploy/prepare_frontend.py
```
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps backend python -m app.cli check
```
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml --profile init run --rm --service-ports certbot-init
```
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
```
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec backend python -m app.cli seed --frontend /frontend
```

1. `prepare_frontend.py` собирает папку `.public/`: только публичные файлы сайта (без документации и служебных файлов), стили склеены в один файл.
2. `app.cli check` показывает, всё ли заполнено.
3. `certbot-init` выпускает HTTPS-сертификат (один раз; порт 80 в этот момент должен быть свободен).
4. `up -d --build` запускает всё; схема базы создаётся сама.
5. `seed` добавляет категории каталога; товары — через админку.

Сайт — `https://<домен>`, админка — `https://<домен>/admin/index.html`.

**Обновление сайта:**
```bash
git pull && python3 deploy/prepare_frontend.py && docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
```

**Пароль администратора без хранения в открытом виде:**
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps backend python -m app.cli hash-password
```
Строку `ADMIN_PASSWORD_HASH='…'` вставьте в `deploy/.env` (в одинарных кавычках), `ADMIN_PASSWORD` оставьте пустым и перезапустите API.

### Резервные копии

Ручная копия прямо сейчас:
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T backup sh -c 'umask 077; pg_dump -Fc -f /backups/kbch-manual.dump && tar czf /backups/media-manual.tgz -C /media .'
```

Восстановление базы из копии (**заменяет текущие данные**, заказы после даты копии пропадут):
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml stop backend
```
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T backup sh -c 'pg_restore --exit-on-error --clean --if-exists -d "$PGDATABASE" /backups/kbch-ДАТА.dump'
```
```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml start backend
```
Восстановление фото и полный порядок отката — [раздел 14](14-Запуск-за-час.md). **Никогда не выполняйте `docker compose down -v`** — это удаляет базу, фото и сертификаты.
Копируйте `deploy/backups/` за пределы сервера: потеря диска сервера уничтожит и локальные копии.

## Вариант 2. Render (без своего сервера)

1. Зарегистрируйтесь на render.com и подключите GitHub.
2. **New → Blueprint →** выберите репозиторий. Render прочитает `render.yaml` и предложит **платные** API, PostgreSQL и диск для фото
   (параметры взяты из render.yaml). Актуальные планы, ограничения и стоимость проверьте в панели перед подтверждением. Для фото нужен постоянный диск, для рабочей базы — подходящая политика хранения и копий.
3. **kbch-api → Environment** — заполните переменные (смысл — в таблице выше): `FRONTEND_URL` (адрес сайта), `PUBLIC_API_URL` (адрес API + `/api`),
   `CORS_ORIGINS` (адрес сайта), администратор, почта, Kaspi. `SECRET_KEY` генерируется сам.
4. **kbch-site → Environment** — `API_URL` (адрес API + `/api`), затем **Manual Deploy**.
5. В админке создайте категории и товары.

## Письма с кодами (Gmail)

`SMTP_USER` — адрес Gmail, `SMTP_PASSWORD` — **пароль приложения**: аккаунт Google → Безопасность → Двухэтапная аутентификация → Пароли приложений.
Обычный пароль Gmail не подойдёт.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Сайт не открывается | `docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps` — все ли контейнеры работают |
| API не запускается | `… logs --tail=100 backend` — сервер пишет, какие настройки исправить |
| Нет HTTPS | DNS домена и `www` указывают на сервер; `… exec web nginx -t` |
| Не приходят письма | `SMTP_USER`, `SMTP_PASSWORD` (пароль приложения), админка → Настройки → «Готовность к запуску» |
| «Слишком много попыток» | сработала защита от перебора — подождать минуту (лимиты — `RATE_*`) |

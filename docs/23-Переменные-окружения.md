# 23. Переменные окружения: все настройки сервера

Эта глава — справочник для человека, который запускает или обслуживает API. Переменная окружения — именованная настройка, которую программа получает при запуске. Например, `COURIER_PRICE=1000` задаёт стоимость курьера. Менять Python-код ради этого не нужно.

Настройки описаны в `backend/app/core/config.py`, в классе `Settings`. Здесь перечислены их имена, значения при отсутствии настройки и назначение. Настоящие пароли и ключи в документацию не включаются.

## Как выглядит настройка

В `.env` одна строка задаёт одно значение:

```ini
ENVIRONMENT=production
COURIER_PRICE=1000
DOCS_ENABLED=false
```

`true` означает «включено», `false` — «выключено». Списки, например способы оплаты, записываются через запятую. Это пример формата, а не готовый полный файл для рабочего сервера. Образец полного набора — `deploy/.env.example`.

## Откуда приложение берёт значения

При обычном запуске приоритет такой, от самого высокого к самому низкому:

1. Переменные запущенного процесса.
2. Файл `backend/.env`.
3. Файл `.env` в текущей рабочей папке.
4. Значения из `Settings`.

Если оба пути `.env` указывают на один файл, это один источник. Для любого режима, кроме точного `ENVIRONMENT=production`, программа дополнительно подставляет локальные значения там, где они оставлены пустыми: SQLite, учебного администратора, журнал писем и реквизиты-примеры.

API сам не ищет `deploy/.env`. При Docker-запуске Compose читает его для подстановок через `--env-file` и передаёт backend через `env_file`. Поля из `environment` в Compose важнее значений `env_file`. На Render настройки задаются в панели хостинга.

После изменения нужен перезапуск процесса. Для Docker после правки `deploy/.env` пересоздайте backend командой из корня проекта:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d backend
```

Обычный `restart` запускает тот же контейнер с прежним окружением и не применяет новые значения.

## Режим, адреса и доступ

| Переменная | Если не задана | Что меняет |
|---|---|---|
| `APP_NAME` | `K-Beauty \| C-Health` | Имя API и описание платежа; название на страницах отдельно задают config/texts |
| `ENVIRONMENT` | `development` | Только точное `production` включает строгую проверку рабочего сервера |
| `SECRET_KEY` | Учебное значение | Секрет подписи; для рабочего сервера нужна случайная строка от 32 символов |
| `FRONTEND_URL` | `http://localhost:5174` | Публичный адрес витрины |
| `PUBLIC_API_URL` | `http://localhost:8000/api` | Публичный адрес API, также нужен для адреса платёжного уведомления |
| `CORS_ORIGINS` | localhost и 127.0.0.1 на порте 5174 | С каких адресов браузерам разрешено обращаться к API |
| `ALLOWED_HOSTS` | `*` | Допустимые имена хоста в запросе; пустой список тоже означает `*` |
| `DOCS_ENABLED` | Автоматический выбор | Схема API включена локально и выключена в production; `true/false` меняет выбор явно |
| `TRUST_PROXY` | `false` | Разрешает брать IP из заголовка X-Forwarded-For от доверенного посредника |
| `PROXY_HOPS` | `1` | Сколько доверенных посредников учитывать при определении IP |

В `CORS_ORIGINS` указывают схему, домен и порт без пути, через запятую. Например, `https://shop.example.kz`. CORS — разрешение браузеру прочитать ответ API; оно не выдаёт права администратора.

Compose сам задаёт production, HTTPS-адреса по `DOMAIN`, CORS, имена хоста, `TRUST_PROXY=true` и `PROXY_HOPS=1`. Для `SECRET_KEY` проверка отклоняет слабые фрагменты из `WEAK_SECRETS`; используйте генератор `python -m app.cli secret`, а не придумывайте строку вручную.

## База данных

| Переменная | Если не задана | Что меняет |
|---|---|---|
| `DATABASE_URL` | Локально — SQLite `backend/dev.db` | Адрес базы; в production обязателен PostgreSQL |
| `DB_POOL_SIZE` | `5` | Обычное число соединений PostgreSQL на один процесс API |
| `DB_MAX_OVERFLOW` | `10` | Дополнительные соединения на процесс при нагрузке |
| `DB_STATEMENT_TIMEOUT_MS` | `15000` | Максимальное время SQL-запроса PostgreSQL в миллисекундах |
| `DB_SSL` | `false` | Защищённое TLS-соединение с PostgreSQL с проверкой сертификата |
| `AUTO_CREATE_TABLES` | `true` | Автоматическое создание таблиц локально на SQLite |

Адреса с `postgres://` и `postgresql://` программа преобразует в `postgresql+asyncpg://`. SQLite использует `sqlite+aiosqlite:///…`. Автосоздание таблиц не заменяет миграции на рабочем сервере.

При нескольких процессах API у каждого свой набор соединений. Например, 2 процесса с настройками 5 + 10 могут потребовать до 30 соединений. Compose задаёт PostgreSQL предел 50; часть соединений нужна служебным действиям. Меняйте число процессов и соединений согласованно.

## Администратор, вход и почтовые коды

| Переменная | Если не задана | Что меняет |
|---|---|---|
| `ADMIN_EMAIL` | Локально `admin@demo.kz` | Адрес единственного серверного администратора |
| `ADMIN_PASSWORD` | Локально `admin12345` | Пароль; в production от 12 символов, без слабых фрагментов |
| `ADMIN_PASSWORD_HASH` | Пусто | Вместо открытого пароля можно задать bcrypt-отпечаток |
| `ADMIN_NAME` | `Администратор` | Имя при создании аккаунта администратора |
| `SESSION_DAYS` | `30` | Сколько дней действует вход |
| `PASSWORD_MIN_LENGTH` | `8` | Минимальная длина пользовательского пароля на сервере |
| `CODE_TTL_MINUTES` | `10` | Срок действия почтового кода в минутах |
| `CODE_RESEND_SECONDS` | `60` | Пауза между повторными отправками кода |
| `CODE_MAX_ATTEMPTS` | `5` | Число попыток ввода одного кода |
| `ALLOWED_EMAIL_DOMAINS` | Пусто | Разрешённые домены почты; пусто — без этого ограничения |

Команду `python -m app.cli hash-password` запускают из `backend` с нужным Python-окружением. Она запросит пароль без отображения и подготовит строку для `.env`. В файле Compose bcrypt-строку сохраняют в одинарных кавычках, чтобы знаки `$` не стали подстановками. Корректный bcrypt-хеш имеет приоритет над `ADMIN_PASSWORD`.

При запуске сервер создаёт или обновляет указанного администратора и снимает роль admin у остальных аккаунтов. `ADMIN_NAME` задаётся при создании; смена этой переменной не переименовывает автоматически существующего пользователя. Если меняете `PASSWORD_MIN_LENGTH`, согласуйте проверку формы в браузере.

## Частота и размер запросов

| Переменная | Если не задана | Что ограничивает |
|---|---|---|
| `RATE_LIMIT_ENABLED` | `true` | Включает ограничения API |
| `RATE_LOGIN` | `10/minute` | Вход и часть чувствительных действий с одного IP |
| `RATE_LOGIN_EMAIL` | `5/minute` | Попытки входа для одного email |
| `RATE_CODES` | `5/minute` | Запросы почтовых кодов |
| `RATE_REGISTER` | `5/hour` | Регистрации |
| `RATE_WRITE` | `60/minute` | Заказы, отзывы, голоса, фото и уведомления оплаты; у действий отдельные группы счётчиков |
| `RATE_GLOBAL` | `300/minute` | Общую частоту запросов к API, кроме health |
| `MAX_BODY_KB` | `1024` | Обычный размер запроса по Content-Length, в КБ |

`10/minute` читается как «10 запросов в минуту». Разрешены единицы `second`, `minute`, `hour`, `day`. Счётчики находятся в памяти каждого процесса: не объединяются между процессами и сбрасываются при перезапуске. У Nginx есть свои ограничения. Это не общий распределённый счётчик на весь сервер.

## Почта

| Переменная | Если не задана | Что меняет |
|---|---|---|
| `EMAIL_BACKEND` | `console` | `console` записывает письмо локально, `smtp` отправляет его; production требует smtp |
| `EMAIL_LOG_FILE` | Локально `backend/dev-mail.log` | Куда записывать учебные письма с кодами |
| `SMTP_HOST` | `smtp.gmail.com` | Адрес почтового сервера |
| `SMTP_PORT` | `587` | Его порт |
| `SMTP_USER` | Пусто | Логин почтового сервера |
| `SMTP_PASSWORD` | Пусто | Пароль почтового сервера |
| `SMTP_FROM` | Пусто | Отправитель; если пусто, используется SMTP_USER |
| `SMTP_TLS` | `true` | STARTTLS на портах кроме 465; на 465 код всегда включает прямое TLS-соединение |

`app.cli check` проверяет заполнение настроек, но не отправляет письмо. Проверяйте доставку настоящей регистрацией тестового аккаунта. Отметка `ready` в админке означает готовность по настройкам, а не подтверждение доставки.

## Доставка и фотографии

| Переменная | Если не задана | Что меняет |
|---|---|---|
| `FREE_SHIPPING_FROM` | `15000` | Сумма товаров, от которой курьер бесплатный, в целых тенге |
| `COURIER_PRICE` | `1000` | Стоимость курьера ниже порога, в тенге |
| `MEDIA_DIR` | Полный путь к `backend/media` | Папка загруженных фотографий |
| `MEDIA_URL` | `/media` | Начало публичного адреса фотографии |
| `MAX_UPLOAD_MB` | `8` | Максимальный размер самого файла фото после чтения base64, в МБ |

Для `courier` действует порог бесплатной доставки. Самовывоз `pickup` стоит 0. Для `kazakhstan` сервер тоже записывает `deliveryPrice=0`: оплата перевозчика учитывается отдельно по правилам магазина. Ноль в этом поле не означает обещание бесплатной перевозки по стране.

При включённом API браузер получает цены доставки через начальный запрос bootstrap. Локальные значения находятся в `frontend/js/config.js`. Если меняете `MEDIA_URL`, согласуйте маршрут Nginx и адреса на клиенте.

| Переменная | Если не задана | Что меняет |
|---|---|---|
| `PAYMENT_METHODS` | `kaspi_transfer,cash,test_card,test_kaspi` | Включённые способы; test_card и test_kaspi только имитируют оплату |
| `KASPI_PHONE` | Локально учебный номер | Номер для ручного перевода |
| `KASPI_RECEIVER` | Локально учебное имя | Получатель ручного перевода |
| `KASPI_PAY_LINK` | Пусто | Необязательная ссылка ручной оплаты |
| `KASPI_API_URL` | `https://kaspi.kz/pay/api` | Адрес внешнего API, записанный в адаптере |
| `KASPI_MERCHANT_ID` | Пусто | Идентификатор магазина во внешнем сервисе |
| `KASPI_API_KEY` | Пусто | Секретный ключ внешнего API |

Наличие адреса и адаптера в коде не подтверждает подключение к боевому Kaspi. Адрес, поля и подпись нужно сверить с договором и документацией провайдера. Подробности — [глава 10](10-Оплата.md) и [глава 24](24-API-и-форматы-данных.md).

## Настройки других инструментов

Следующие имена не входят в `Settings`, но используются при запуске:

| Переменная | Где читается | Значение или назначение |
|---|---|---|
| `DOMAIN` | Compose и Nginx | Домен без `https://` и `www` |
| `LETSENCRYPT_EMAIL` | Compose, certbot-init | Почта владельца сертификата |
| `POSTGRES_DB`, `POSTGRES_USER` | Compose | Имя базы и пользователя; по умолчанию `kbch` |
| `POSTGRES_PASSWORD` | Compose | Пароль базы; из него также строится DATABASE_URL |
| `BACKUP_KEEP_DAYS` | Compose, backup | Сколько дней хранить копии; по умолчанию 14 |
| `WEB_CONCURRENCY` | `backend/entrypoint.sh` | Число процессов API; по умолчанию 2, в render.yaml — 1 |
| `PORT` | `backend/entrypoint.sh` | Порт API, по умолчанию 8000 |
| `API_URL` | Команда сборки на Render | Публичный адрес API, записываемый в env.js |
| `TEST_DATABASE_URL` | Серверные тесты | Адрес отдельной тестовой PostgreSQL; без него создаётся временная SQLite |

`PGHOST`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `KEEP_DAYS` передаются сервису backup из Compose. `PG_URL` в workflow указывает на одноразовую тестовую базу. `PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED`, `PIP_NO_CACHE_DIR` задаются в Dockerfile и управляют работой Python/pip.

`window.KBCH_API_URL`, `window.KBCH_STORAGE_PREFIX`, `window.KBCH_EXTENSIONS` — настройки JavaScript в браузере. Это не переменные Windows или Linux. Они записываются в публичные файлы сайта и демо.

## Как проверить заполнение

Для рабочего сервера нужны настоящие адреса, PostgreSQL, администратор, случайный секрет, SMTP и реквизиты включённых оплат. Перед реальными заказами уберите `test_card,test_kaspi` из `PAYMENT_METHODS`.

Из корня проекта, где настроен Docker, выполните:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml config --quiet
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps backend python -m app.cli check
```

Первая команда проверяет Compose без вывода всех секретных значений. Вторая проверяет правила приложения. Ошибочный тип, например текст вместо числа, может быть отклонён ещё при чтении Settings. Успешный результат не проверяет доставку писем, DNS, сертификаты и доступность платёжного сервиса: эти действия проверяются отдельно.

# 20. Библиотеки, зависимости и инструменты

Сведения ниже взяты из файлов проекта. Это используемые версии, а не утверждение о самых новых выпусках. Источник установки — `backend/requirements.txt`, для разработки — `backend/requirements-dev.txt`.

**Библиотека** подключается к программе. **Фреймворк** задаёт каркас приложения. **Драйвер** соединяет приложение с базой. **Инструмент** запускается отдельно. **Зависимость** — общий термин для того, что нужно другой программе.

В `requirements-dev.txt` сначала стоит `-r requirements.txt`: это означает установить также весь основной список. Затем идут:

| Библиотека | Версия | Назначение |
|---|---|---|
| `pytest` | `8.3.4` | Сбор и выполнение Python-тестов, фикстуры, параметризация |
| `pytest-asyncio` | `0.24.0` | Выполнение асинхронных тестов и фикстур |

**Pydantic** используется напрямую в коде (`BaseModel`, `Field`, валидаторы), но отдельной закреплённой строки `pydantic==…` в requirements нет: пакет приходит через зависимости. Аналогично устанавливаются служебные зависимости Alembic, Uvicorn и других библиотек. Полного lock-файла со всеми транзитивными версиями в репозитории нет. Поэтому фиксированные прямые версии не гарантируют побайтово одинаковое окружение при установках в разное время.

## Установка и проверка окружения

Из корня проекта, PowerShell:

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-dev.txt
backend/.venv/Scripts/python.exe -m pip check
```

На Linux/macOS путь к интерпретатору — `backend/.venv/bin/python`. Активация окружения необязательна, если указан полный путь к его Python. Для production устанавливается `requirements.txt`, а Docker делает это сам при сборке образа.

Проверить версии в конкретном окружении можно командой `python -m pip show fastapi starlette pydantic` (после активации нужного окружения). Для локальной фиксации фактической установки существует `python -m pip freeze`. Результат описывает окружение конкретного запуска; он не заменяет проверку совместимости при обновлении.

## Фронтенд: браузерные возможности вместо npm-библиотек

В текущем проекте нет `package.json`, npm lock-файла, React, Vue, Bootstrap, Tailwind, Vite или Webpack. Фронтенд запускается без `npm install`. Компоненты, карусели, формы и SVG-иконки находятся в собственных JS/CSS-файлах.

| Возможность браузера | Для чего применяется |
|---|---|
| DOM и события | Создание интерфейса и обработка действий |
| Fetch API | JSON-запросы к серверу |
| localStorage | Корзина, избранное, сессия и кеш данных |
| URLSearchParams | Параметры каталога и переходов |
| Intl | Форматирование значений |
| IntersectionObserver | Реакции на появление блоков при прокрутке |
| Canvas / API работы с изображениями | Подготовка фотографий в админке |
| CSS Grid, Flexbox, media queries | Сетки и адаптивный интерфейс |

Google Fonts — внешний источник шрифтов **Cormorant Garamond**, **Manrope**, **Caveat**. Шрифты подключены ссылками в HTML. При недоступности сервиса браузер использует резервные шрифты из CSS. Иконки в `core/icons.js` и favicon — SVG, отдельной библиотеки иконок нет.

## Среда и инфраструктура

| Инструмент | Как задан в проекте | Роль |
|---|---|---|
| Python | `3.11` в CI и `python:3.11-slim` в Docker | Сервер, сборки, Python-тесты |

| SQLite | Через Python-драйвер aiosqlite | Локальная база-файл |
| Nginx | `nginx:1.27-alpine` | Статика, прокси API, HTTPS, заголовки и лимиты |
| Certbot | `certbot/certbot:v2.11.0` | Получение и продление сертификатов |
| Docker / Compose v2 | `backend/Dockerfile`, `deploy/docker-compose.yml` | Сборка и совместный запуск сервисов |

Теги Docker и версии Actions (`@v4`, `@v5`) не закреплены неизменяемым digest/SHA. Это отличается от полного воспроизводимого набора артефактов.

## Как обновлять зависимости

Изменить нужные строки requirements, установить их в отдельное окружение, выполнить `pip check`, серверные тесты на SQLite и PostgreSQL и миграционные проверки CI. Для обновления браузерной логики выполнить JS-тесты и ручную проверку соответствующего сценария. После изменения зависимостей production заново собрать Docker-образ.

Автоматического линтера Python, TypeScript-компиляции, отдельного npm-сборщика и отчёта покрытия в текущих workflows нет. Их нельзя считать уже настроенными только по наличию правил игнорирования соответствующих кешей.

# 19. Основы HTML, CSS, JavaScript и Python

Эта глава нужна, если вы хотите понимать код и менять сайт самостоятельно. Для добавления товаров через админку учить языки программирования не требуется. Здесь — основные понятия на примерах магазина. Подробности находятся в главах [4](04-Фронтенд-HTML-страницы.md), [5](05-Фронтенд-CSS-оформление-и-адаптивность.md), [6](06-Фронтенд-JavaScript.md) и [7](07-Бэкенд-Python.md).

## Кто за что отвечает

Представьте карточку товара. HTML сообщает браузеру: «Здесь название, фотография и кнопка». CSS задаёт цвет, размер и расположение. JavaScript реагирует на кнопку и добавляет товар в корзину. Когда покупатель оформляет заказ, Python на сервере проверяет данные, считает сумму и сохраняет заказ в базе.

| Технология | Что делает | Пример файла |
|---|---|---|
| HTML | Задаёт элементы страницы | `frontend/pages/catalog.html` |
| CSS | Оформляет страницу | `frontend/css/components/product-card.css` |
| JavaScript, сокращённо JS | Управляет действиями в браузере | `frontend/js/pages/catalog.js` |
| Python | Обрабатывает запросы на сервере и запускает служебные программы | `backend/app/main.py` |

HTML, CSS и JS получает браузер посетителя. Python работает на сервере или компьютере разработчика. Посетитель может изменить код в своём браузере, поэтому сервер заново проверяет права, цены и остатки. Одной проверки в форме недостаточно.

## HTML: из чего состоит страница

**Тег** обозначает элемент: заголовок, кнопку, картинку. **Атрибут** уточняет его свойства. Например, у ссылки `href` хранит адрес перехода.

```html
<button type="button" class="example-button" id="buy-button">
  В корзину
</button>
```

Здесь `button` — кнопка, `type="button"` — обычное действие без отправки формы. `class` связывает кнопку с оформлением, `id` помогает найти именно эту кнопку в коде. Надпись между тегами увидит покупатель. Это учебный пример, его не нужно добавлять на сайт.

| Запись | Простое объяснение |
|---|---|
| `<!doctype html>` | Сообщает браузеру, что это современная HTML-страница |
| `<html lang="ru">` | Начало документа и его язык |
| `<head>` | Настройки: название вкладки, стили, скрипты |
| `<body>` | Содержимое, которое показывается на странице |
| `<header>`, `<main>`, `<footer>`, `<nav>` | Шапка, основная часть, подвал и навигация |
| `<h1>`–`<h6>` | Заголовки: от главного к более мелким |
| `<p>` | Обычный абзац |
| `<a href="…">` | Ссылка |
| `<button type="submit">` | Кнопка отправки формы |
| `<form>`, `<label>`, `<input>` | Форма, подпись к полю и поле ввода |
| `<select>`, `<textarea>` | Список выбора и большое текстовое поле |
| `<img src="…" alt="…">` | Картинка: адрес файла и описание для случая, когда её нельзя увидеть |
| `id="grid"` | Уникальное имя одного элемента на странице |
| `class="products-grid"` | Имя оформления; одинаковый класс может быть у многих элементов |
| `aria-label`, `aria-live`, `aria-hidden` | Подсказки для программ, которые озвучивают сайт; `aria-hidden` скрывает от озвучивания декор |

У проекта есть свои атрибуты:

| Атрибут | Зачем он нужен |
|---|---|
| `data-page="catalog"` | Загрузчик понимает, что нужно включить логику каталога |
| `data-base="../"` | Показывает путь из вложенной страницы к корню сайта |
| `data-t="catalog.title"` | Подставляет текст с этим ключом из словаря `frontend/texts/ru/catalog.js` |

Браузер превращает HTML в дерево элементов. Это дерево называется **DOM**. JavaScript может найти в нём блок и добавить карточки товаров. Поэтому без JavaScript большая часть магазина не появится: сервер не присылает полностью готовые страницы с товарами.

Как читать адреса в HTML:

- `../css/main.css`: подняться на одну папку и открыть CSS-файл.
- `/api/products`: начать от корня текущего домена.
- `?slug=cream`: передать параметр в адресе.
- `#orders`: перейти к нужному разделу интерфейса.

## CSS: как задаётся внешний вид

```css
.example-button {
  color: white;
  background: var(--primary);
  padding: 12px 20px;
  border-radius: 12px;
}
```

Точка перед `example-button` означает: «Применить оформление ко всем элементам с таким классом». Внутри скобок перечислены свойства. `color` — цвет текста, `background` — фон, `padding` — внутренний отступ, `border-radius` — скругление. `var(--primary)` берёт общий цвет из `frontend/css/base/variables.css`.

Это учебный класс. При реальной правке сначала найдите существующий стиль нужного элемента.

| Понятие | Для чего применяется |
|---|---|
| `margin`, `padding`, `border` | Внешний отступ, внутренний отступ и рамка |
| Flexbox | Расположение элементов в строке или столбце |
| Grid | Сетка карточек товаров и фотографий |
| `position: sticky`, `fixed` | Закрепление блока при прокрутке или относительно окна |
| `:hover`, `:focus-visible`, `:disabled` | Вид при наведении, выборе клавиатурой и отключённой кнопке |
| `@media` | Другие правила для телефона, планшета или особых настроек пользователя |
| `transition`, `@keyframes` | Плавные изменения и анимации |
| `px`, `%`, `rem` | Размер в пикселях, долях родительского блока или относительно основного шрифта |
| `@import` | Подключение другого CSS-файла |

Пример правила для узкого экрана:

```css
@media (max-width: 760px) {
  .example-button { width: 100%; }
}
```

Если ширина окна не больше 760 пикселей, кнопка займёт всю доступную ширину.

Иногда один элемент подходит под несколько правил. Браузер выбирает правило по **каскаду**: учитывает источник, точность селектора, `!important` и порядок. Если остальные условия одинаковые, побеждает более позднее правило. Поэтому одного переноса строки ниже бывает недостаточно для исправления стиля.

Правьте файлы в `frontend/css/`. Перед публикацией сборщик объединяет CSS в `.public/`. Изменение только готовой `.public/` пропадёт при следующей сборке.

## JavaScript: действия и данные

В магазине используется обычный JavaScript без отдельного фреймворка интерфейса. Файлы связаны общим объектом `window.App`. Загрузчик `frontend/js/app.js` подключает их в нужном порядке. Это важно: в текущем проекте нет подключения этих файлов через `import/export`.

| Запись | Что означает |
|---|---|
| `const`, `let` | Создать переменную; `let` допускает последующее присваивание другого значения |
| `{ name: 'Крем' }` | Объект — набор полей с именами |
| `[]` | Массив — список значений |
| `map`, `filter`, `find` | Преобразовать список, отобрать элементы, найти один элемент |
| `function`, `=>` | Описать функцию: действие, которое можно вызвать |
| `addEventListener` | Выполнить действие при клике, вводе или другом событии |
| `querySelector` | Найти элемент страницы |
| Шаблонная строка | Собрать строку из обычного текста и значений переменных |
| `Promise`, `async`, `await` | Дождаться запроса, пока браузер продолжает обрабатывать другие события |
| `try/catch` | Обработать ошибку и показать понятное сообщение |
| `(() => { … })()` | Сразу запустить функцию и оставить её внутренние переменные внутри файла |

Порядок запуска сайта: `app.js` читает `env.js`, при включённом API запрашивает `/bootstrap`, загружает общие файлы и файлы страницы. Затем `core/start.js` запускает интерфейс и отправляет событие `app:ready`. При изменении хранилища появляется событие `store:change`: другие части страницы узнают, что нужно обновить данные.

**localStorage** — память конкретного браузера для конкретного адреса сайта. Схема адреса, домен и порт учитываются отдельно. Например, `localhost:5174` и `localhost:5175` имеют разную память. Корзина и избранное остаются в браузере даже при включённом API. На другом телефоне эта корзина сама не появится. Очистка данных браузера может её удалить.

Текст, введённый посетителем, нельзя без проверки превращать в HTML. Используйте существующие помощники экранирования: они показывают специальные символы как текст. `ui.applyTexts()` вставляет доверенные тексты из файлов проекта через `innerHTML`; для непроверенных сообщений посетителя этот способ не подходит.

## Python: серверная часть

Python-файл называют **модулем**. Папку с файлом `__init__.py` — **пакетом**. В Python отступы определяют, какие строки относятся к одному действию. В серверных исходниках сохранён отступ 4 пробела. Общий `.editorconfig` задаёт 2 пробела, поэтому в `.py` ориентируйтесь на окружающий код.

Пример по мотивам проверки сервера:

```python
@router.get('/health')
async def health(db: AsyncSession = Depends(get_db)):
    await db.scalar(select(1))
    return {'status': 'ok'}
```

Это сокращение, которое объясняет идею. В настоящем файле `backend/app/api/routers/health.py` есть обработка ошибки базы. Общий префикс `/api` добавляется при подключении маршрута, поэтому полный адрес — `/api/health`.

| Запись | Что означает |
|---|---|
| `import`, `from … import …` | Подключить код из другого файла или библиотеки |
| `def`, `return` | Описать функцию и вернуть её результат |
| `async def`, `await` | Описать действие, которое может ждать базу или сеть |
| `@router.get(…)` | Назначить функции адрес для GET-запроса |
| `class Settings(BaseSettings)` | Создать класс настроек на основе готового класса библиотеки |
| `str`, `int`, `bool`, `list`, `dict` | Строка, целое число, «да/нет», список, словарь |
| `str \| None` | Разрешена строка или отсутствие значения |
| `Depends(get_db)` | FastAPI подготавливает доступ к базе и передаёт его функции |
| `raise HTTPException(…)` | Остановить запрос и вернуть код ошибки |
| `async with` | Использовать ресурс и корректно закрыть его после работы |

Указание `str` или `int` рядом с переменной помогает читать код, но само по себе не проверяет всю программу. В запросах проверку полей выполняет Pydantic. База дополнительно проверяет свои ограничения. Ожидание через `await` помогает обслуживать другие действия во время сетевых операций; количество серверных процессов отдельно задаёт Gunicorn.

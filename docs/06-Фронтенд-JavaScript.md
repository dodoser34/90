# 6. Работа кнопок и страниц: JavaScript

## Зачем нужен JavaScript

**JavaScript**, сокращённо JS, — язык программирования, который выполняется в браузере. В этом проекте он показывает товары, реагирует на кнопки, проверяет формы, ведёт корзину и обращается к серверу.

Файлы находятся в `frontend/js/`. Проект использует обычный JavaScript без React и Vue — дополнительных систем построения интерфейса. Для локального просмотра отдельная сборка JavaScript не нужна.

Этот раздел помогает найти нужный файл. Общие основы языка с примерами — [раздел 19](19-Основы-HTML-CSS-JS-Python.md).

## Что происходит при открытии страницы

1. Браузер читает HTML и запускает `frontend/js/app.js` — загрузчик остальных файлов.
2. Загрузчик читает `frontend/env.js`. Если адрес API не пустой, сайт запрашивает начальные данные у сервера по `/bootstrap`.
3. Загружаются общие настройки, тексты, работа с данными и повторяющиеся элементы интерфейса.
4. Подключаются файлы выбранной страницы. Её имя задано атрибутом `data-page` в HTML.
5. `core/start.js` вставляет тексты, создаёт шапку и подвал, затем сообщает остальным частям, что можно начинать. Это сообщение называется событием `app:ready`.
6. Код страницы показывает её содержимое.

Во время загрузки страница сначала скрывается; через шесть секунд скрытие снимается даже при задержке. Это ограничивает ожидание, но не исправляет ошибку, если один из необходимых файлов не загрузился.

## Общие помощники: `core/`

**Модуль** — отдельный файл с определённой задачей. Общие модули используют разные страницы.

| Файл | Для чего нужен |
|---|---|
| `utils.js` | Форматирует цену и телефон, строит ссылки, помогает находить элементы и безопасно выводить текст |
| `texts.js` | Берёт надписи из `texts/ru/`, вставляет значения и подбирает форму слова, например «5 товаров» |
| `icons.js` | Содержит значки и логотип |
| `auth-guard.js` | Направляет гостя на вход со страниц, где нужна авторизация |
| `start.js` | Выполняет общую подготовку страницы |

**Авторизация** — проверка того, какие действия разрешены пользователю. Перенаправление в браузере помогает интерфейсу; окончательная проверка прав рабочего магазина выполняется сервером.

## Данные: `store/` и `App.db`

Большинство операций страниц с товарами, пользователями, заказами и отзывами проходит через `App.db`. Это общее имя набора функций работы с данными.

**localStorage** — небольшое постоянное хранилище браузера для данного адреса сайта. В режиме без сервера туда записываются данные магазина. В режиме с сервером часть данных остаётся там как **кеш** — местная копия для отображения. Главные записи тогда находятся в серверной базе.

| Файлы | За что отвечают |
|---|---|
| `storage.js` | Чтение и запись localStorage, сообщения об изменениях |
| `products.js`, `categories.js` | Товары и категории |
| `users.js`, `session.js` | Локальные аккаунты и текущий вход |
| `cart.js`, `favorites.js` | Корзина и избранное; они остаются в браузере и при работе с сервером |
| `orders.js`, `reviews.js` | Заказы и отзывы |
| `media.js` | Заменённые фотографии страницы «О нас» |
| `init.js` | Начальная подготовка пустого хранилища |
| `remote.js` | Связывает операции с серверным API и обновляет местные копии данных |

Такой способ подключения называется **адаптером**: страницы используют знакомые функции, а нужная реализация обращается к браузеру или серверу. Это не делает режимы одинаковыми по безопасности или общности данных.

Корзина и избранное не становятся общими для всех устройств автоматически. Удаление данных браузера может удалить их, даже если покупатель пользуется серверным аккаунтом.

## Общие элементы: `components/`

Здесь находятся части, которые встречаются на нескольких страницах:

- `header.js`, `mobile-menu.js`, `footer.js` — шапка, меню телефона и подвал.
- `product-card.js`, `carousel.js` — карточки товаров и прокручиваемые подборки.
- `cart-favorites-actions.js` — добавление в корзину и избранное, счётчики.
- `images.js`, `lightbox.js` — изображения, замены отсутствующих картинок и просмотр фото крупно.
- `modal.js`, `toast.js` — отдельные окна и короткие уведомления.
- `reveal.js`, `transitions.js` — появление блоков и переходы.
- `benefits.js`, `payment-info.js` — преимущества магазина и инструкция по оплате заказа.

## Код конкретной страницы: `pages/`

Имя основного файла обычно совпадает со страницей: `home.js` — главная, `cart.js` — корзина, `checkout.js` — оформление, `pay.js` — тестовая оплата, `login.js` — вход.

Крупные страницы разделены на несколько файлов. У каталога есть `catalog-state.js`, `catalog-filters.js`, `catalog-toolbar.js` и `catalog-results.js`: состояние фильтров, панель фильтров, управление и результаты. У товара — отдельные файлы галереи, информации, отзывов, формы отзыва и данных для поисковиков. Личный кабинет использует `account.js` и `account-views.js`.

## Управление магазином: `admin/`

`admin-app.js` создаёт меню, проверяет доступ и переключает разделы. Остальные файлы названы по задачам: `dashboard.js`, `products-list.js`, `categories.js`, `orders.js`, `users.js`, `reviews.js`, `site-photos.js`, `settings.js`.

Форма товара разделена между `product-form.js`, `product-form-template.js`, `product-images.js` и `form-controls.js`. `image-tools.js` уменьшает фотографии перед загрузкой.

## Где менять тексты и настройки

Большинство надписей покупательской части находится в `frontend/texts/ru/`: `common.js` содержит общие подписи, остальные файлы соответствуют страницам. В админ-панели эти тексты не редактируются.

`frontend/js/config.js` хранит общие настройки магазина. Список `adminEmails` нужен только для режима без сервера. Серверного администратора он не назначает.

Для перевода на другой язык недостаточно скопировать папку `ru`: нужны перевод всех ключей, согласование языка HTML, форматов и сообщений сервера. Готового переключателя языка в проекте нет.

## Технические подробности: запросы и обновление файлов

Сайт и сервер обмениваются данными в **JSON** — текстовом формате с именованными полями. После входа сервер выдаёт **токен**, то есть случайную строку для подтверждения входа. Браузер сохраняет её и передаёт в заголовке запроса `Authorization: Bearer …`.

Адрес API задаёт `frontend/env.js`. Ошибка сервера обычно показывается пользователю в уведомлении. Поля запросов и ответов описаны в [разделе 24](24-API-и-форматы-данных.md).

Число `VERSION` в `app.js` и окончания `?v=…` у подключений в HTML помогают браузеру скачать обновлённые файлы. При изменении версии их нужно согласовать согласно [разделу 25](25-Сборка-деплой-и-сопровождение.md).

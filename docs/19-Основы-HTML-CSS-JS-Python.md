# 19. Основы HTML, CSS, JavaScript и Python

Этот раздел объясняет технологии на примерах именно этого магазина. Подробное устройство страниц — [4](04-Фронтенд-HTML-страницы.md), стилей — [5](05-Фронтенд-CSS-оформление-и-адаптивность.md), скриптов — [6](06-Фронтенд-JavaScript.md), сервера — [7](07-Бэкенд-Python.md).

## Четыре технологии в одном действии

Покупатель нажимает «В корзину». **HTML** задаёт кнопку, **CSS** задаёт её вид, **JavaScript** обрабатывает нажатие и меняет корзину в браузере. При оформлении заказа JavaScript отправляет запрос, а **Python** на сервере проверяет аккаунт, товары, остатки и рассчитывает сумму. База сохраняет заказ.

| Технология | Что это | Где выполняется | Пример в проекте |
|---|---|---|---|
| HTML | Язык разметки документов | Браузер | `frontend/pages/catalog.html` |
| CSS | Язык описания оформления | Браузер | `frontend/css/components/product-card.css` |
| JavaScript | Язык программирования интерфейса | Браузер; в тестах также Node.js | `frontend/js/pages/catalog.js` |
| Python | Язык программирования сервера и служебных утилит | Сервер, компьютер разработчика, CI | `backend/app/main.py`, `deploy/prepare_frontend.py` |

HTML и CSS сами по себе не принимают заказы и не проверяют пароль. JavaScript в браузере доступен посетителю для просмотра и изменения, поэтому права и итоговую стоимость проверяет API на Python.

## HTML: теги, атрибуты и документ

Тег задаёт вид элемента, атрибут уточняет его свойства. Пример из каркаса каталога:

```html
<html lang="ru" data-base="../">
  <head>
    <meta charset="utf-8" />
    <link rel="stylesheet" href="../css/main.css?v=23" />
    <script src="../js/app.js?v=23" data-page="catalog"></script>
  </head>
  <body data-page="catalog">
    <header id="site-header"></header>
    <main>
      <h1 id="cat-title" data-t="catalog.title"></h1>
      <div class="products-grid" id="grid"></div>
    </main>
    <footer id="site-footer"></footer>
  </body>
</html>
```

Это сокращённый пример, а не замена полного файла: у настоящей страницы также есть `doctype`, `viewport`, CSP, шрифты и прочие элементы.

| Запись | Значение |
|---|---|
| `<!doctype html>` | Документ использует современный HTML |
| `lang="ru"` | Язык документа; загрузчик также выбирает папку текстов по языку |
| `<head>` | Настройки страницы, заголовок вкладки, стили, скрипты |
| `<body>` | Содержимое страницы |
| `<header>`, `<main>`, `<footer>`, `<nav>` | Смысловые области: шапка, основной материал, подвал, навигация |
| `<h1>`–`<h6>`, `<p>` | Заголовки разного уровня и абзац |
| `<a href="…">` | Ссылка на другую страницу или раздел |
| `<button type="button">` | Кнопка действия; `submit` отправляет форму |
| `<form>`, `<label>`, `<input>`, `<select>`, `<textarea>` | Форма, подпись, поле, выбор и многострочный текст |
| `<img src="…" alt="…">` | Изображение и его текстовое описание |
| `id="grid"` | Уникальное имя элемента на странице; используется JS и CSS |
| `class="products-grid"` | Имя группы оформления; класс можно повторять |
| `data-page` | Собственная метка проекта: какую логику страницы загрузить |
| `data-base="../"` | Как из вложенной страницы дойти до корня сайта |
| `data-t="catalog.title"` | Ключ надписи из `frontend/texts/ru/catalog.js` |
| `aria-label`, `aria-live`, `aria-hidden` | Подсказки для вспомогательных технологий; `aria-hidden` исключает декоративный элемент из озвучивания |

Браузер строит из HTML **DOM** — дерево элементов. JavaScript находит узлы дерева и добавляет карточки, сообщения, меню. Без JavaScript значительная часть магазина не появится: серверного рендеринга страниц в проекте нет.

Пути `../css/main.css` относительные: `..` означает подняться на одну папку. Адрес `/api/products` начинается от корня домена. `?slug=…` — параметры запроса, `#orders` — фрагмент адреса для раздела интерфейса.

## CSS: селекторы, свойства и каскад

Учебный пример в стиле проекта:

```css
.example-button {
  color: white;
  background: var(--primary);
  padding: 12px 20px;
  border-radius: 12px;
}

@media (max-width: 760px) {
  .example-button { width: 100%; }
}
```

`.example-button` — селектор класса, внутри фигурных скобок идут пары «свойство: значение». `var(--primary)` читает общую переменную цвета из `css/base/variables.css`. Это учебный класс; в исходниках следует использовать существующие компоненты.

**Каскад** определяет победившее правило. Важны не только порядок файлов, но и специфичность селектора, источник правила и `!important`. При одинаковой силе побеждает более позднее правило. Поэтому адаптивные стили подключаются после основных.

| Механизм | Для чего нужен в магазине |
|---|---|
| Box model: `margin`, `border`, `padding`, содержимое | Отступы и размеры карточек и кнопок |
| Flexbox | Выстроить элементы строки, шапки, панели действий |
| Grid | Сетки товаров и мозаика фотографий |
| `position: sticky` / `fixed` | Закреплённые элементы интерфейса |
| `:hover`, `:focus-visible`, `:disabled` | Наведение, фокус клавиатуры, недоступная кнопка |
| `@media` | Правила для размеров экрана, сенсорного ввода и уменьшенного движения |
| `transition`, `@keyframes` | Переходы и анимации |
| `px`, `%`, `rem`, единицы высоты экрана | Фиксированные и относительные размеры |
| `@import` | Подключение CSS-модулей в исходниках |

На сервере Python-утилита объединяет импорты в `main.css` и `admin.css`. Править нужно исходники `frontend/css/`, затем повторно собирать `.public/`.

## JavaScript: данные, функции, события

В проекте используются обычные браузерные скрипты. Общий объект `window.App` связывает модули. Это не система ES-модулей с `import/export`: порядок подключения задаётся в `frontend/js/app.js`.

| Конструкция | Смысл | Где встречается |
|---|---|---|
| `const`, `let` | Переменные: ссылка без переназначения / с переназначением | Логика страниц и хранилища |
| Объект `{ name: '…' }` | Запись с именованными полями | Товар, заказ, настройки |
| Массив `[]`, `map`, `filter`, `find` | Список, преобразование, отбор, поиск | Каталог и корзина |
| Функция, `=>` | Повторно вызываемое действие | `App.db`, `App.ui` |
| `addEventListener` | Реакция на клик, ввод, готовность документа | Компоненты и страницы |
| `querySelector` | Поиск элемента DOM | Помощники `App.ui` |
| Шаблонная строка | Сборка строки из текста и значений | Разметка карточек и адреса API |
| `Promise`, `async`, `await` | Ожидание результата запроса без блокировки всего интерфейса | `store/remote.js` |
| `try/catch` | Обработка ошибки | Запросы и чтение localStorage |
| IIFE: `(() => { … })()` | Изоляция внутренних переменных файла | Большинство модулей |

Жизненный цикл: `app.js` → `env.js` → при наличии API `/bootstrap` → общие модули → модули страницы → `core/start.js` → событие `app:ready`. Изменение данных сообщает о себе событием `store:change`.

**localStorage** — память конкретного браузера для данного origin (схема + домен + порт). Корзина и избранное остаются локальными даже при включённом API; серверные данные в браузере являются кешем. Два браузера не разделяют такую корзину. Инкогнито и очистка данных могут её удалить.

Пользовательский текст перед вставкой в HTML необходимо экранировать через существующие помощники. `ui.applyTexts()` использует `innerHTML` для доверенных текстов из файлов проекта; это не способ выводить непроверенные данные посетителя.

## Python: модули, типы, классы и асинхронность

Python-файл называется **модулем**, папка с `__init__.py` — пакетом. Отступы задают блоки кода. Серверные файлы проекта используют отступ 4 пробела; общий `.editorconfig` при этом задаёт 2 пробела, подробнее — [21](21-Конфигурационные-файлы.md).

```python
@app.get('/api/health')
async def health(db: AsyncSession = Depends(get_db)):
    await db.scalar(select(1))
    return {'status': 'ok'}
```

Это сокращение действующего обработчика из `backend/app/api/routers/health.py`; в полном варианте есть обработка недоступной базы с HTTP 503.

| Запись | Что означает |
|---|---|
| `import`, `from … import …` | Подключить другой модуль или библиотеку |
| `def`, `return` | Объявить функцию, вернуть результат |
| `async def`, `await` | Асинхронная функция и ожидание операции ввода-вывода |
| `@app.get(…)` | Декоратор: назначить функции адрес GET-запроса |
| `class Settings(BaseSettings)` | Класс настроек, расширяющий поведение библиотеки |
| `str`, `int`, `bool`, `list`, `dict` | Строка, целое число, логическое значение, список, словарь |
| `str \| None` | Строка или отсутствие значения |
| `Depends(get_db)` | FastAPI передаёт подготовленное соединение с базой |
| `raise HTTPException(…)` | Завершить запрос с определённым HTTP-статусом |
| `async with` | Открыть ресурс и корректно закрыть его после работы |

Аннотация типа сама по себе не проверяет любой Python-код. В API проверку входящих данных выполняет Pydantic, а ограничения хранения дополнительно задаются базой. Асинхронность помогает во время ожидания базы и почты; число процессов регулируется отдельно через Gunicorn.

## Остальные языки и форматы

| Расширение / формат | Что означает | Файл проекта |
|---|---|---|
| JSON | Данные: объект, массив, строки, числа, `true/false/null`; комментариев нет | `demo/config.json`, ответы API |
| YAML | Настройки с вложенностью через отступы | `deploy/docker-compose.yml`, `render.yaml`, workflows |
| INI | Секции `[имя]` и пары ключ-значение | `pytest.ini`, `backend/alembic.ini` |
| `.env` | Переменные окружения; это настройки, а не скрипт | Шаблон `deploy/.env.example` |
| Markdown (`.md`) | Заголовки, ссылки, таблицы, блоки кода документации | Эта папка |
| SQL | Язык базы данных; в приложении запросы в основном строит SQLAlchemy | Модели и миграции |
| Shell (`.sh`) | Команды Linux-контейнера | `backend/entrypoint.sh` |
| SVG | Векторные изображения в XML-разметке | `frontend/favicon.svg`, иконки |
| CommonJS (`.cjs`) | Модули Node.js с `require` и `module.exports` | `tests/frontend/` |
| Mako (`.mako`) | Шаблон генерируемого Python-файла | `backend/migrations/script.py.mako` |

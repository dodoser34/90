# 23. Полный справочник переменных окружения

Источник настроек API — класс `Settings` в `backend/app/core/config.py`. Имена его полей в окружении записываются заглавными буквами. Значения ниже — исходные defaults, если отдельно не указана подстановка development или Compose. Реальные значения секретов документация не содержит.

## Откуда берутся значения

При обычном запуске Settings читает окружение процесса и файлы `.env` в текущей папке и `backend/.env`; более поздний файл в списке имеет приоритет между dotenv-файлами, переменные процесса важнее dotenv. Если значение не задано, используется default, затем локальные подстановки `dev_defaults()`.

`deploy/.env` API автоматически не ищет. При Docker-запуске Compose читает его через `--env-file` для подстановок и через `env_file: .env` передаёт значения backend-контейнеру. Явное `environment` в Compose перекрывает переданные значения. На Render настройки передаются из панели хостинга.

После изменения настроек нужен перезапуск процесса; Settings кешируется `lru_cache`. После изменения `deploy/.env` используйте `docker compose … up -d backend`: простой `restart` не пересоздаёт окружение контейнера.

## Приложение, адреса, доступ

| Переменная | Default | Назначение |
|---|---|---|
| `APP_NAME` | `K-Beauty \| C-Health` | Имя API и описания платежа; название на сайте также есть в config/texts |
| `ENVIRONMENT` | `development` | Только точное `production` включает production-проверки |
| `SECRET_KEY` | Небезопасное локальное значение | HMAC-подписи; production требует случайную строку ≥32 символов без слабых слов |
| `FRONTEND_URL` | `http://localhost:5174` | Публичный адрес витрины |
| `PUBLIC_API_URL` | `http://localhost:8000/api` | Публичный адрес API, в том числе callbackUrl платежа |
| `CORS_ORIGINS` | localhost и 127.0.0.1 на 5174 | Разрешённые origin через запятую, без путей |
| `ALLOWED_HOSTS` | `*` | Допустимые Host; пустой список тоже даёт `*` |
| `DOCS_ENABLED` | `None` | По умолчанию docs доступны в development и выключены в production; true/false явно меняет выбор |
| `TRUST_PROXY` | `false` | Читать IP из X-Forwarded-For за доверенным прокси |
| `PROXY_HOPS` | `1` | Число доверенных звеньев при выборе IP из цепочки |

Compose задаёт production, HTTPS-адреса от `DOMAIN`, список Host, CORS, `TRUST_PROXY=true`, `PROXY_HOPS=1`. CORS управляет браузерным доступом, а не заменяет проверку токена и роли.

## База данных

| Переменная | Default | Назначение |
|---|---|---|
| `DATABASE_URL` | Пусто | В development подставляется SQLite `backend/dev.db`; в production обязателен PostgreSQL |
| `DB_POOL_SIZE` | `5` | Базовый пул PostgreSQL на процесс |
| `DB_MAX_OVERFLOW` | `10` | Дополнительные соединения на процесс при нагрузке |
| `DB_STATEMENT_TIMEOUT_MS` | `15000` | Таймаут SQL PostgreSQL в миллисекундах |
| `DB_SSL` | `false` | TLS с проверкой через стандартный SSL context для PostgreSQL |
| `AUTO_CREATE_TABLES` | `true` | Создание таблиц при development + SQLite; не заменяет production-миграции |

Префиксы `postgres://` и `postgresql://` нормализуются в `postgresql+asyncpg://`. Для локального файла применяется `sqlite+aiosqlite:///…`. При нескольких worker число потенциальных соединений растёт вместе с числом процессов. Compose задаёт базе `max_connections=50`, поэтому настройки пула и worker нужно согласовывать.

## Администратор, сессии, коды

| Переменная | Default | Назначение |
|---|---|---|
| `ADMIN_EMAIL` | Пусто → `admin@demo.kz` локально | Единственный серверный администратор |
| `ADMIN_PASSWORD` | Пусто → `admin12345` локально | Пароль; для production ≥12 символов и без слабых слов |
| `ADMIN_PASSWORD_HASH` | Пусто | Альтернатива открытому паролю; bcrypt-хеш |
| `ADMIN_NAME` | `Администратор` | Имя при создании аккаунта |
| `SESSION_DAYS` | `30` | Срок сессии в днях |
| `PASSWORD_MIN_LENGTH` | `8` | Минимальная длина пользовательского пароля в серверной проверке |
| `CODE_TTL_MINUTES` | `10` | Срок кода подтверждения/сброса |
| `CODE_RESEND_SECONDS` | `60` | Минимальная пауза повторной отправки |
| `CODE_MAX_ATTEMPTS` | `5` | Допустимое число попыток кода |
| `ALLOWED_EMAIL_DOMAINS` | Пусто | Список разрешённых почтовых доменов; пусто — без такого ограничения |

Получить хеш можно через `python -m app.cli hash-password` из backend. В Compose bcrypt-строку сохраняют в одинарных кавычках, чтобы `$` не воспринимался как подстановка. При наличии корректного bcrypt-хеша он имеет приоритет применения над ADMIN_PASSWORD. Администратор синхронизируется при запуске, у других аккаунтов роль admin снимается.

Фронтенд содержит собственные правила длины пароля, поэтому изменение `PASSWORD_MIN_LENGTH` требует согласования UI. Смена ADMIN_NAME в окружении не является общей командой переименования уже существующего пользователя: `ensure_admin()` задаёт имя при создании.

## Ограничения запросов

| Переменная | Default | Назначение |
|---|---|---|
| `RATE_LIMIT_ENABLED` | `true` | Включить серверный limiter |
| `RATE_LOGIN` | `10/minute` | Вход и некоторые чувствительные действия по IP |
| `RATE_LOGIN_EMAIL` | `5/minute` | Попытки входа для адреса почты |
| `RATE_CODES` | `5/minute` | Запросы отправки кодов |
| `RATE_REGISTER` | `5/hour` | Регистрация |
| `RATE_WRITE` | `60/minute` | Запись: заказы, отзывы, голоса, загрузки, webhook по своим scope |
| `RATE_GLOBAL` | `300/minute` | Общий лимит API, кроме health |
| `MAX_BODY_KB` | `1024` | Обычный размер тела запроса по Content-Length |

Формат лимита — целое число, `/` и одно из `second`, `minute`, `hour`, `day`. Счётчики API находятся в памяти каждого процесса, не объединены между worker и сбрасываются при перезапуске. Внешний Nginx имеет отдельные лимиты. Эти механизмы не гарантируют защиту от распределённой атаки на канал связи.

## Почта

| Переменная | Default | Назначение |
|---|---|---|
| `EMAIL_BACKEND` | `console` | Локальная запись либо `smtp`; production требует smtp |
| `EMAIL_LOG_FILE` | Пусто → `backend/dev-mail.log` локально | Журнал локальных писем с кодами |
| `SMTP_HOST` | `smtp.gmail.com` | Почтовый сервер |
| `SMTP_PORT` | `587` | Порт SMTP |
| `SMTP_USER` | Пусто | Пользователь почтового сервера |
| `SMTP_PASSWORD` | Пусто | Секрет SMTP |
| `SMTP_FROM` | Пусто | Отправитель; при отсутствии используется SMTP_USER |
| `SMTP_TLS` | `true` | STARTTLS при порте не 465; для 465 код включает прямой TLS независимо от этого флага |

`app.cli check` проверяет заполнение и ограничения, но не выполняет пробную SMTP-отправку. Доставку подтверждают реальной регистрацией на тестовом аккаунте. Значение `ready` в админке также не является доказательством доставки письма.

## Доставка и фотографии

| Переменная | Default | Назначение |
|---|---|---|
| `FREE_SHIPPING_FROM` | `15000` | Порог бесплатного курьера, целые тенге |
| `COURIER_PRICE` | `1000` | Стоимость курьера ниже порога |
| `MEDIA_DIR` | `backend/media` как абсолютный путь | Физическое место загруженных фото |
| `MEDIA_URL` | `/media` | URL-префикс раздачи файлов |
| `MAX_UPLOAD_MB` | `8` | Максимальный размер декодированного фото |

Для доставки `kazakhstan` сервер записывает deliveryPrice=0: оплата перевозчика учитывается отдельно по принятой в магазине схеме. Условие бесплатной доставки применяется к `courier`, самовывоз также даёт 0. Фронтенд получает серверные параметры через bootstrap; локальные defaults есть в `frontend/js/config.js`. При смене MEDIA_URL нужно согласовать Nginx и клиентские ссылки.

## Дополнительные настройки Compose, entrypoint и сборщика

Эти имена не являются полями Settings:

| Переменная | Где читается | Значение / смысл |
|---|---|---|
| `DOMAIN` | Compose, шаблон Nginx | Домен без схемы и www |
| `LETSENCRYPT_EMAIL` | Compose certbot-init | Почта владельца сертификата |
| `POSTGRES_DB`, `POSTGRES_USER` | Compose | По умолчанию `kbch` |
| `POSTGRES_PASSWORD` | Compose | Пароль базы; используется при построении DATABASE_URL |
| `BACKUP_KEEP_DAYS` | Compose backup | По умолчанию 14; передаётся как KEEP_DAYS |
| `WEB_CONCURRENCY` | entrypoint.sh | По умолчанию 2; render.yaml задаёт 1 |
| `PORT` | entrypoint.sh | По умолчанию 8000 |
| `API_URL` | Render build command | Публичный адрес API для записываемого env.js |
| `TEST_DATABASE_URL` | backend/tests/conftest.py | Только отдельная тестовая PostgreSQL-база; без него временная SQLite |

`PGHOST`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `KEEP_DAYS` внутри backup заполняются Compose. `PG_URL` в workflow — адрес одноразовой базы CI. `PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED`, `PIP_NO_CACHE_DIR` задаются Dockerfile для среды Python.

`window.KBCH_API_URL`, `window.KBCH_STORAGE_PREFIX`, `window.KBCH_EXTENSIONS` — JavaScript-настройки браузера, не переменные окружения ОС. Они находятся в публичном env.js и демо-сборке.

## Проверка перед запуском

В development достаточно defaults. Для production укажите настоящие адреса, PostgreSQL, администратора, секрет, SMTP и реквизиты включённых методов. Отключите `test_card,test_kaspi` перед реальными заказами. Пример — `deploy/.env.example`.

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml config --quiet
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps backend python -m app.cli check
```

Первая команда проверяет Compose без печати полного окружения; вторая проверяет правила приложения. Они не проверяют всю доступность DNS, SMTP, сертификатов и платёжного провайдера. Проверки production перечислены в `Settings.problems()`; ошибочный тип некоторых полей Pydantic отклонит ещё до этой функции.

# 10. Оплата

Способы оплаты включаются одной строкой в `deploy/.env`:

```env
PAYMENT_METHODS=kaspi_transfer,cash,test_card,test_kaspi
```

Покупатель видит при оформлении только **включённые и полностью настроенные** способы. Что настроено, а чего не хватает,
показывает **админка → Настройки → «Готовность к запуску»** и команда `python -m app.cli check`.
В рабочем режиме сервер не запустится, если включённому способу не хватает настроек.

| Код | Способ | Что нужно | Статус |
|---|---|---|---|
| `kaspi_transfer` | Перевод на Kaspi владельца | `KASPI_PHONE`, `KASPI_RECEIVER` | работает сразу |
| `cash` | Наличными или картой курьеру при получении | ничего | работает сразу |
| `test_card` | **Тестовая оплата картой** (имитация) | ничего | работает сразу |
| `test_kaspi` | **Тестовая оплата через Kaspi** (имитация) | ничего | работает сразу |
| `kaspi_pay` | Kaspi Pay для бизнеса: оплата в приложении с автоматическим подтверждением | `KASPI_MERCHANT_ID`, `KASPI_API_KEY`, `KASPI_WEBHOOK_SECRET` | адаптер; боевой контракт требует сверки |

Статусы оплаты заказа: **«При получении»**, **«Ждёт оплаты»**, **«Оплачен»**, **«Не прошла»**, **«Возврат»**.
Сумму к оплате всегда считает сервер по ценам из базы — подменить её из браузера нельзя.

---

## Перевод на Kaspi

```env
KASPI_PHONE=+7 700 123 45 67
KASPI_RECEIVER=Наргиз К.
KASPI_PAY_LINK=
```
`KASPI_PHONE` — номер, привязанный к Kaspi Gold; `KASPI_RECEIVER` — имя получателя, как его видит покупатель;
`KASPI_PAY_LINK` — (необязательно) ссылка Kaspi Pay или QR для оплаты в один клик.

1. Покупатель оформляет заказ → видит номер Kaspi, получателя, сумму и комментарий «Заказ №1001» (номер и комментарий копируются кнопкой).
2. Заказ получает статус **«Ждёт оплаты»**; реквизиты видны и в личном кабинете.
3. Деньги пришли → админка → **Заказы** → заказ → **Оплата → Оплачен**.

## Наличными при получении

Настроек не требует. Статус — «При получении»; после оплаты администратор отмечает «Оплачен».

## Тестовая оплата картой и через Kaspi

Нужна, чтобы показать и проверить весь путь онлайн-оплаты **до подключения настоящего эквайринга**. Работает и на сервере в интернете.
Деньги не списываются, номер карты нигде не сохраняется — в заказ записываются только последние 4 цифры.

**Как проходит:**
1. Покупатель выбирает «Банковская карта (тестовая оплата)» или «Kaspi (тестовая оплата)» и оформляет заказ.
2. Его сразу переводит на страницу **«Оплата заказа»** (`pages/pay.html`). Неоплаченный заказ можно оплатить позже — кнопкой «Перейти к оплате» в личном кабинете.
3. **Карта:** форма с «живой» картой. Сервер проверяет номер (алгоритм Луна), срок и CVC, как настоящий банк.
   **Kaspi:** QR-код и кнопка «Открыть Kaspi» → имитация экрана приложения → «Подтвердить оплату» или «Отменить».
4. Заказ становится **«Оплачен»** — это видно покупателю в кабинете и администратору в админке.

| Тестовая карта | Результат |
|---|---|
| `4242 4242 4242 4242` | оплата проходит |
| `4000 0000 0000 0002` | банк отклоняет платёж (статус «Не прошла», можно попробовать ещё раз) |
| `4000 0000 0000 9995` | недостаточно средств |

Срок — любой будущий (например `12/30`), CVC — любые 3 цифры. На странице есть кнопки «Подставить».

Защита: оплатить можно только свой заказ; оплаченный заказ повторно не оплачивается; отменённый — не оплачивается;
если убрать `test_card`/`test_kaspi` из `PAYMENT_METHODS`, тестовая оплата сразу перестаёт работать.

> **Перед приёмом настоящих платежей** уберите `test_card` и `test_kaspi` из `PAYMENT_METHODS`.

Код: `backend/app/services/payments/sandbox.py` (проверка карты, отказ банка), адрес `POST /api/payments/sandbox/{заказ}`,
страница `frontend/pages/pay.html` + `frontend/js/pages/pay.js` + `frontend/css/pages/pay.css`.

## Kaspi Pay для бизнеса (когда будет доступ к API)

В коде реализованы создание счёта, переход на оплату, обработка уведомления, проверка подписи и суммы, обработка повторов. Это контракт адаптера, а не подтверждение работы с боевым Kaspi Pay. URL, формат полей, авторизацию и подпись необходимо сверить с официальными условиями конкретного провайдера и проверить в его среде. Подробности реализованного контракта — [24](24-API-и-форматы-данных.md).

1. Подключите магазин к Kaspi Pay и получите в кабинете доступ к API (ID магазина, ключ API, секрет для уведомлений).
2. В `deploy/.env`:
   ```env
   PAYMENT_METHODS=kaspi_transfer,cash,kaspi_pay
   KASPI_MERCHANT_ID=…
   KASPI_API_KEY=…
   KASPI_WEBHOOK_SECRET=…
   ```
3. В кабинете Kaspi укажите адрес уведомлений: `https://<домен>/api/payments/kaspi/webhook`.
4. Программист сверяет с документацией Kaspi Pay три места в `backend/app/services/payments/kaspi_pay.py`:
   - `start()` — адрес создания счёта (`<KASPI_API_URL>/invoices`), названия полей запроса (`merchantId`, `orderId`, `amount`, `currency`, `returnUrl`, `callbackUrl`)
     и ответа (`invoiceId`, `paymentUrl`);
   - `check_signature()` — как Kaspi подписывает уведомления (сейчас: HMAC-SHA256 тела запроса секретом, заголовок `X-Signature`);
   - `parse_webhook()` — названия полей уведомления (`orderId`, `status`, `amount`).
5. Перезапуск: `docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d backend`. Проверьте заказом на небольшую сумму.

Как сервер обрабатывает уведомление Kaspi:
- без верной подписи — отказ, запись в журнале;
- сумма не совпадает с заказом — отказ, заказ не отмечается оплаченным;
- заказ уже оплачен — повторное уведомление ничего не меняет;
- пока `kaspi_pay` выключен, адрес уведомлений не отвечает.

## Как добавить новый способ оплаты

Все способы — в папке `backend/app/services/payments/`:

```
payments/
├─ __init__.py        список способов (METHODS), выбор включённых, проверка готовности
├─ base.py            общий вид способа: code, title, text, env, start(), instructions()
├─ kaspi_transfer.py  перевод на Kaspi
├─ cash.py            при получении
├─ sandbox.py         тестовая оплата картой и через Kaspi
└─ kaspi_pay.py       Kaspi Pay API: счёт, подпись и разбор уведомления
```

1. Скопируйте `kaspi_pay.py` в новый файл (например, `cloudpayments.py`), поменяйте `code`, `title`, `text`, список нужных настроек `env` и запрос в `start()`.
2. Добавьте класс в `METHODS` в `payments/__init__.py` и поля настроек в `backend/app/core/config.py`.
3. Если сервис присылает уведомления — добавьте адрес по образцу `kaspi_webhook` в `backend/app/api/routers/orders.py` (подпись → сумма → повтор).
4. Добавьте код способа в `PAYMENT_METHODS`. Сайт покажет новый способ сам — фронтенд менять не нужно.

**Метод «стратегия»:** каждый способ — отдельный файл с одинаковым набором действий, остальной код от них не зависит.

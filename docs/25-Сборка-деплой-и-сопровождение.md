# 25. Сборка, обновление и сопровождение

Эта глава нужна человеку, который публикует магазин и затем поддерживает сервер. Первую публикацию выполняйте по [главе 13](13-Публикация-на-сервере.md) или [главе 14](14-Запуск-за-час.md). Здесь объясняется, что происходит при сборке и как обновлять уже работающий проект.

**Сборка** готовит файлы для посетителей. **Развёртывание**, или deploy, размещает их на сервере и запускает приложение. В этом проекте Python готовит витрину, Docker упаковывает API, а Compose запускает базу, API и остальные сервисы вместе.

## Какой запуск выбрать

Команды выполняются из корня проекта.

| Задача | Команда или способ | Результат |
|---|---|---|
| Смотреть изменения витрины | `python deploy/serve_frontend.py` | Раздаётся исходная папка frontend, порт 5174 |
| Посмотреть магазин с примерами | `python demo/serve.py` | Собирается и открывается демо, порт 5175 |
| Подготовить демо без запуска | `python demo/build.py` | Готовая папка `demo/.public/` |
| Подготовить рабочую витрину | `python deploy/prepare_frontend.py` | Готовая `.public/` в корне |
| Запустить рабочий API | Dockerfile и entrypoint через Compose | Backend-контейнер |

Node.js нужен для проверок JavaScript, а не для сборки витрины. Изменение `frontend/env.js` говорит браузеру, куда обращаться, но не настраивает сервер и разрешённые адреса CORS.

## Что делает сборщик витрины

`deploy/prepare_frontend.py` выполняет следующие действия:

1. Проверяет папку `frontend/` и путь результата, чтобы не заменить постороннюю папку.
2. Готовит временную папку в корне проекта.
3. Копирует разрешённые файлы из pages, admin, css, js, texts и assets, а также разрешённые корневые файлы.
4. Исключает служебные и скрытые папки, ссылки на другие файлы, секреты, тесты, копии и временные материалы по своим правилам.
5. Объединяет локальные CSS-импорты верхнего уровня. Порядок правил сохраняется, пути к изображениям пересчитываются. JS и CSS не сжимаются автоматически.
6. По необязательному флагу `--api-url-from-env` читает адрес API из указанной переменной и записывает публичный `env.js`.
7. Проверяет результат, заменяет свою `.public/` и записывает отметку `.public-build.json`.

В адресе API запрещены логин/пароль, параметры после `?` и фрагмент после `#`. Относительный адрес должен начинаться с одного `/`, например `/api`.

Список разрешённых имён включает index.html, 404.html, env.js, .nojekyll, robots.txt, sitemap.xml и значок сайта. Это список допуска. Сборщик не создаёт robots.txt и sitemap.xml сам.

Если непустая `.public/` не имеет правильной отметки сборщика, замена остановится. Сначала выясните, что лежит в папке. Подделывать отметку для обхода проверки не нужно. Старый результат удаляется при замене, поэтому этот способ не гарантирует обновление без перерыва.

Пример записи отдельного адреса API, Windows PowerShell:

```powershell
$env:API_URL = 'https://api.example.kz/api'
python deploy/prepare_frontend.py --api-url-from-env API_URL
```

Замените учебный адрес настоящим. В Docker-схеме сайт и API работают на одном домене: Nginx подставляет `deploy/env.js` со значением `/api`. На Render адрес записывает команда сборки из `render.yaml`. В Pages публикуется демо с пустым API и своим расширением.

## Какие сервисы запускает Compose

**Контейнер** — отдельный запущенный сервис Docker. **Том**, или volume, — хранилище, которое переживает пересоздание контейнера.

| Сервис | Что делает | Постоянные данные |
|---|---|---|
| db | Хранит записи в PostgreSQL 16 | Том pgdata |
| backend | Проверяет настройки, применяет миграции, запускает API | Том media с фото; `.public/` читает для начального наполнения |
| web | Принимает запросы через Nginx и отдаёт сайт | Читает `.public/`, фото и сертификаты |
| certbot | Пытается продлевать HTTPS-сертификаты | Тома letsencrypt и certbot-www |
| certbot-init | Один раз получает первый сертификат, запускается с профилем init | Том letsencrypt |
| backup | Копирует базу и архивирует фотографии, удаляет старые копии по сроку | Папка `deploy/backups/` на сервере |

База и API не открывают внешние порты в этой схеме. `expose: 8000` описывает порт для других контейнеров. Backend подключён к внутренней сети базы и к сети для внешних сервисов. Для первого получения сертификата certbot-init нужен свободный порт 80; web запускается после этого шага.

`restart: unless-stopped` перезапускает завершившийся контейнер. Healthcheck показывает, отвечает ли сервис. Пометка unhealthy сама по себе не означает, что Docker его автоматически исправит. Backend ждёт готовности базы, а web по своему depends_on не ждёт полной готовности API.

## Как Nginx направляет запросы

Nginx — внешний вход в магазин. Обычный HTTP перенаправляется на HTTPS, кроме пути проверки сертификата ACME. Адрес с `www` приводится к основному домену, неизвестное имя хоста отклоняется.

| Адрес | Куда направляется |
|---|---|
| `/api/…` | В backend:8000 с сохранением `/api` |
| `/media/…` | В постоянную папку фотографий |
| `/env.js` | В публичные настройки без кеширования |
| HTML, CSS, JS, изображения | В готовую `.public/` |
| Несуществующий файл | Ответ 404 с пользовательской страницей `404.html` |
| Скрытый или запрещённый служебный файл | Ответ 404 |

**Кеш** — сохранённая копия файла, чтобы не загружать его заново. Nginx разрешает кешировать файлы оформления и скрипты до 7 дней, фото media — до 30 дней. После изменения нужно обновлять версии `?v=…` в HTML и `VERSION` загрузчика. Демо рассчитывает версию по содержимому само; production-сборщик автоматическую версию JS/HTML не присваивает. При прямом просмотре исходников учитывайте также версии CSS-импортов.

## Как обновить работающий сервер

Следующие команды — Bash на Linux VPS, из корня проекта. Перед ними сохраните копии базы и media по главе 13, запишите текущую версию кода и прочитайте новые миграции. Во время обновления активные запросы могут прерваться.

```bash
git rev-parse HEAD
git pull --ff-only
python3 deploy/prepare_frontend.py
docker compose --env-file deploy/.env -f deploy/docker-compose.yml config --quiet
docker compose --env-file deploy/.env -f deploy/docker-compose.yml build backend
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps backend python -m app.cli check
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
```

Что ожидать: Git покажет старую версию и получит изменения; сборщик обновит витрину; Compose проверит настройки, соберёт API и запустит сервисы. При запуске backend автоматически выполнит миграции. Последняя команда покажет состояние контейнеров. Если один шаг завершился ошибкой, сначала разберите её, прежде чем переходить к следующему.

После запуска откройте HTTPS-сайт и `/api/health`, проверьте вход, каталог, фото и ранее созданный заказ. Если меняли конфигурацию Nginx, проверьте её и примените:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec web nginx -t
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec web nginx -s reload
```

Выполняйте reload только после успешного `nginx -t`. При смене DOMAIN или окружения web его нужно пересоздать, чтобы шаблон получил новые значения. Автоматическое применение миграций не делает любую будущую миграцию безопасной: до запуска проверяются её изменения и резервная копия.

## Если что-то не работает

Для начала посмотрите последние сообщения API и Nginx:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml logs --tail=100 backend web
```

| Проблема | Что проверить |
|---|---|
| Backend не запускается | Ошибки чтения Settings, обязательные production-настройки, права папки фото и миграции |
| Nginx отвечает 502 | Работает ли backend, слушает ли порт 8000; что пишут журналы web/backend |
| Health отвечает 503 | Работает ли db и доступно ли соединение с базой |
| Каталог пустой | Куда смотрит env.js, есть ли товары именно в этой базе, опубликованы ли они |
| Браузер сообщает CORS | Совпадают ли схема, домен и порт с CORS_ORIGINS; правильный ли адрес API |
| Фото исчезли после обновления | Сохранён ли том/диск, верны ли PUBLIC_API_URL и ссылки media |
| Письмо не приходит | Настройки SMTP, доступ к почтовому серверу, папку спама; нужна реальная тестовая отправка |
| Видна старая версия сайта | Правильная ли `.public/`, выполнена ли сборка, изменены ли версии файлов и очищен ли кеш |
| Ответ 429 | Какой лимит сработал в API/Nginx; сколько ждать по Retry-After |
| Сборщик отказался заменить папку | Путь результата и отметку владения; сначала выясните причину |

Журналы могут содержать контакты покупателей. Просмотрите их перед отправкой другому человеку. Для проверки Compose используйте `config --quiet`: обычный `config` выводит подставленные настройки, включая секреты.

## Резервные копии и восстановление

Backup делает первую попытку сразу, затем примерно раз в сутки. Успешная пара файлов выглядит как `kbch-ДАТА.dump` и `media-ДАТА.tgz`: база и фотографии. При сбое временные файлы удаляются, старые копии сохраняются.

База и фото копируются последовательно. Это не один одновременный снимок: учитывайте фото, загруженные между этими операциями. Срок хранения задаёт `BACKUP_KEEP_DAYS`, по умолчанию 14 дней.

Копии в `deploy/backups/` находятся на том же сервере. Для защиты от его потери переносите их также в другое место. Облачное копирование и проверка его успеха в Compose не настроены. Просматривайте журнал backup и периодически проверяйте восстановление в отдельной среде.

Порядок восстановления базы и media и отката описан в [главе 14](14-Запуск-за-час.md). Возврат старого кода не возвращает автоматически прежнюю схему и данные. Команда `docker compose down -v` удаляет постоянные тома, в том числе базу, фото и сертификаты; это не команда обычного обновления.

## Чем отличаются Render и GitHub Pages

`render.yaml` описывает PostgreSQL, API с постоянным диском и статическую витрину. Nginx, Certbot и backup из Compose там не запускаются. Соответствующие функции и копии нужно настраивать средствами хостинга. Планы в YAML — параметры репозитория; их доступность и стоимость проверяются в панели перед заказом.

GitHub Pages публикует только `demo/.public/`. Настоящий Python API и PostgreSQL там не запускаются. Аккаунты, заказы и имитация оплаты демо находятся в браузере. Подробнее — [глава 15](15-Демо-версия.md).

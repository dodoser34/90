# 7. Серверная часть: Python

## Что делает сервер

**Бэкенд**, или серверная часть, — программа, которая принимает запросы сайта, проверяет пользователя и данные, работает с базой и возвращает результат. Например: «этот пользователь может открыть заказ», «товара осталось две штуки», «сумма заказа такая».

Код написан на Python и находится в `backend/app/`. Основная библиотека — FastAPI. **Библиотека** — готовый набор возможностей, который использует программа.

Для обычного управления магазином менять этот код не нужно. Он понадобится, когда меняются правила работы: оформление, оплата, права, состав данных или проверка форм.

## Как проходит запрос

Запрос приходит на адрес `/api/…`. Общий защитный слой проверяет размер и частоту обращений. Затем нужный обработчик проверяет вход, права и поля, читает или меняет базу, вызывает дополнительные сервисы и возвращает ответ.

**Обработчик** — функция для конкретного адреса и действия. **Сервис** — код отдельной задачи, например отправки письма или создания платежа. **Схема данных** — правила полей: что обязательно, какой тип, допустимая длина и формат.

## Где искать нужную часть

Пути в таблице указаны внутри `backend/app/`.

| Файл или папка | Что делает |
|---|---|
| `main.py` | Точка запуска приложения |
| `application.py` | Соединяет обработчики, настройки доступа и защитные проверки |
| `lifecycle.py` | Проверяет настройки, готовит локальную базу и администратора, закрывает соединения при остановке |
| `cli.py` | Служебные команды из терминала |
| `core/config.py` | Настройки сервера и проверка готовности |
| `core/security.py` | Пароли, токены и коды из писем |
| `core/rate_limit.py` | Ограничение частоты действий и определение IP посетителя |
| `core/sanitize.py` | Очистка текста и проверка адресов изображений |
| `core/middleware.py` | Общие проверки запросов, заголовки и обработка неожиданных ошибок |
| `db/models.py` | Описание таблиц базы |
| `db/session.py` | Подключение к базе |
| `schemas/` | Правила входящих данных |
| `services/emails.py` | Отправка писем или запись локальных писем в файл |
| `services/payments/` | Способы оплаты |
| `services/seed.py` | Начальные категории из файлов сайта |
| `api/deps.py` | Проверка текущего пользователя и роли администратора |
| `api/serializers.py` | Преобразование записей базы в ответ для сайта |
| `api/routers/` | Обработчики API по разделам магазина |

В `api/routers/` файл `auth.py` отвечает за аккаунты, `catalog.py` — за каталог и фото, `orders.py` — за заказы и оплату, `reviews.py` — за отзывы. `site.py` содержит общие данные сайта, пользователей админ-панели, начальную загрузку `/bootstrap` и проверку настроек. `health.py` проверяет доступность базы.

Это деление по задачам. Перед изменением посмотрите импорты — строки, которыми файл подключает другие части. Нельзя считать папки полностью независимыми только из-за их названий.

## Какие библиотеки используются

Списки установки лежат в `backend/requirements.txt` и `backend/requirements-dev.txt`. Второй добавляет инструменты разработки и проверки. Прямые зависимости имеют заданные версии; полного файла с версиями всех вложенных зависимостей нет.

| Библиотека | Простое назначение |
|---|---|
| FastAPI, Starlette | Принимают запросы, формируют ответы, подключают общие проверки |
| Pydantic, pydantic-settings | Проверяют поля и читают настройки |
| email-validator | Проверяет форму адреса электронной почты |
| Uvicorn | Запускает приложение и принимает подключения |
| Gunicorn | На сервере запускает несколько рабочих процессов приложения |
| SQLAlchemy | Помогает читать и изменять базу из Python |
| asyncpg, aiosqlite | Подключают соответственно PostgreSQL и SQLite |
| Alembic | Применяет записанные изменения структуры базы |
| bcrypt | Создаёт защищённые отпечатки паролей |
| httpx | Отправляет запросы внешнему сервису оплаты |
| aiosmtplib | Отправляет письма через почтовый сервер |
| pytest, pytest-asyncio | Запускают автоматические проверки |

Подробности версий и инструментов — [раздел 20](20-Библиотеки-и-инструменты.md).

## Основные группы API

API — правила общения сайта с сервером. Метод `GET` обычно означает получение, `POST` — выполнение действия или создание, `PATCH` — изменение отдельных полей, `DELETE` — удаление.

| Адрес или группа | Для чего |
|---|---|
| `/api/auth/…` | Регистрация, подтверждение почты, вход, выход, профиль, пароли |
| `/api/categories`, `/api/products` | Каталог; изменение доступно администратору |
| `/api/uploads` | Загрузка фото администратором |
| `/api/orders`, `/api/orders/my` | Создание заказа и заказы вошедшего покупателя |
| `/api/admin/orders`, `/api/admin/users` | Управление заказами и пользователями |
| `/api/reviews`, `/api/products/{id}/reviews` | Просмотр отзывов и действия с ними |
| `/api/payments/methods` | Доступные способы оплаты |
| `/api/payments/sandbox/{order_id}` | Тестовая оплата своего заказа |
| `/api/payments/kaspi/webhook` | Приём подписанного уведомления от платёжного адаптера |
| `/api/site`, `/api/site/photos` | Фото страницы «О нас» |
| `/api/bootstrap` | Начальные данные страницы одним запросом |
| `/api/admin/system` | Проверка настроек для администратора |
| `/api/health` | Проверка сервера и базы: ответ 200 при успехе, 503 при недоступной базе |

Фигурные скобки в адресе означают место конкретного значения, а не текст для буквального ввода. Полный список методов, полей и прав — [раздел 24](24-API-и-форматы-данных.md).

Локально можно открыть **http://localhost:8000/api/docs** и попробовать запросы. Изменяющие запросы действительно меняют данные выбранной базы. В рабочем режиме эта страница по умолчанию выключена; уведомление Kaspi в неё не включено.

## Служебные команды на своём компьютере

Команды ниже выполняются в PowerShell **из папки `backend`** после установки библиотек по разделу 2. Они используют Python виртуального окружения.

```powershell
.\.venv\Scripts\python.exe -m app.cli check
```

Команда показывает настройки и недостающие поля, не выводя значения секретов. В локальном режиме она может перечислить то, что потребуется только для публикации; это не мешает локальному запуску.

Остальные команды вводятся там же:

| Окончание команды | Действие |
|---|---|
| `-m app.cli secret` | Показать новый случайный `SECRET_KEY` |
| `-m app.cli hash-password` | Запросить пароль дважды и выдать его отпечаток для `ADMIN_PASSWORD_HASH` |
| `-m app.cli seed` | Добавить начальные категории |
| `-m app.cli admin` | Применить администратора из текущих настроек |

Перед каждым окончанием ставьте `.\.venv\Scripts\python.exe`, как в полном примере выше. Генерация секрета или хеша сама не записывает его в настройки: полученную строку нужно сохранить в нужном `.env` и держать в секрете.

На сервере используйте команды внутри контейнера согласно [разделу 13](13-Публикация-на-сервере.md). Контейнер — отдельное окружение запуска, созданное Docker.

## Два набора настроек

В локальном режиме `development` используются `backend/dev.db`, локальный администратор `admin@demo.kz` / `admin12345` и письма в `backend/dev-mail.log`. Эти значения подходят только для проверки.

В рабочем режиме `production` нужны PostgreSQL, адрес сайта, почта и собственные секреты. Проверка `problems()` в `core/config.py` запрещает запуск при обнаруженных ошибках настройки. Прохождение этой проверки ещё не подтверждает доставку письма или работу настоящего платёжного провайдера.

При запуске через Docker Compose настройки из `deploy/.env` передаются в контейнер. Обычный локальный Python сам этот файл из `deploy/` не подхватывает. Правила и приоритеты настроек — [раздел 23](23-Переменные-окружения.md).

# 15. Демо-версия: посмотреть и попробовать

Демо — отдельная копия витрины с примерными товарами, отзывами и аккаунтами. Она нужна для показа интерфейса и безопасной тренировки. Её можно открыть локально или разместить на GitHub Pages.

В демо нет общей серверной базы, настоящих писем и списания денег. Изменения сохраняются в вашем браузере: другой человек или другой браузер их не увидит. Демо-аккаунты не дают доступ к рабочему магазину.

## Открыть демо на своём компьютере

**Что нужно:** Python и папка проекта. Для чтения документации Python не нужен.

1. Откройте PowerShell в корне проекта — в папке, где находятся `frontend`, `backend` и `demo`.
2. Выполните:

```powershell
python demo/serve.py
```

3. Дождитесь строки с адресом и откройте в браузере `http://localhost:5175`.
4. Чтобы завершить показ, вернитесь в окно PowerShell и нажмите `Ctrl + C`.

**Результат:** открывается заполненная витрина. Команда сначала собирает её в `demo/.public/`, затем запускает локальный просмотр. Если порт занят, укажите другой: `python demo/serve.py 5176`, затем откройте `http://localhost:5176`.

## Попробовать покупателя и администратора

1. Откройте страницу входа.
2. В блоке «Быстрый вход для проверки» выберите роль.
3. Покупателем добавьте товар в корзину и оформите примерный заказ. Администратором откройте панель и попробуйте изменить товар или состояние заказа.

| Роль | Почта и пароль |
|---|---|
| Покупатель | `buyer@demo.kz` / `demo123` |
| Администратор | `admin@demo.kz` / `admin123` |

«Забыли пароль?» показывает тестовый код `246810`; письмо не отправляется. Код вводят после запроса восстановления. Имитация оплаты происходит в браузере. Не вводите настоящие реквизиты карты.

Если эксперименты мешают, откройте админ-панель → «Настройки» → действие сброса демо и подтвердите его. Сброс заменяет данные этого браузера исходными примерами. Нужную выгрузку JSON скачайте до сброса.

## Где находятся части демо

| Путь в `demo/` | Назначение |
|---|---|
| `data/`, `images/products/` | Примерные данные и фотографии |
| `runtime/`, `css/ui.css` | Быстрый вход, тестовые действия и их оформление |
| `config.json` | Список дополнений и отдельные ключи хранения в браузере |
| `build.py`, `serve.py` | Сборка и локальный просмотр |
| `github-pages/action.yml` | Действие публикации GitHub Pages |
| `seed_backend.py` | Отдельная загрузка примеров в локальный API для разработки; рабочий режим запрещён кодом |
| `tests/` | Автоматические проверки демо |

Обычный сайт берётся из `frontend/`, а демо добавляет свои данные и поведение. Основная публикация `deploy/prepare_frontend.py` не включает демо-наполнение. Не переносите примеры в рабочую базу.

## Опубликовать показ на GitHub Pages

1. Откройте репозиторий в GitHub → Settings → Pages.
2. В Source выберите GitHub Actions.
3. Запустите workflow «GitHub Pages — demo» из Actions либо отправьте подходящее изменение в `main`.
4. Дождитесь успешной публикации и откройте адрес, показанный GitHub.

Автозапуск предусмотрен для изменений `frontend/`, `demo/`, сборщика и workflow Pages. Правка только документации не обязана запускать публикацию.

Чтобы убрать демо из проекта, удаляют `demo/` и `.github/workflows/pages.yml`. Чтобы закрыть уже опубликованный показ, дополнительно отключают GitHub Pages в настройках репозитория. Рабочий магазин не требует этих файлов.

## Что сохраняется в Git

Git хранит исходники, документацию, тесты и образцы настроек. Правила `.gitignore` исключают обычные `.env`, локальную базу, загруженные фото, копии и результаты сборки. Для проверки конкретных путей из корня проекта:

```powershell
git check-ignore -v deploy/.env backend/dev.db
```

**Результат:** команда показывает правила исключения этих файлов. Это не проверка всей истории Git: если секрет уже был добавлен раньше, удаление файла не отменяет раскрытие. Такой секрет нужно заменить.

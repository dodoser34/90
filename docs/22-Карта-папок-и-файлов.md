# 22. Карта папок и файлов

Краткая архитектура — [3](03-Устройство-проекта.md). Здесь — справочник назначения файлов и маршруты чтения кода. Все пути даны от корня репозитория. Одинаковые по назначению файлы объединены в группы.

## `tests/` и `docs/`

`tests/frontend/helpers.cjs` создаёт ограниченную имитацию браузерного окружения в Node VM. `utils.test.cjs` проверяет помощники, `store.test.cjs` — хранилище, `catalog.test.cjs` — логику каталога. `tests/general/test_public_build.py` проверяет безопасный состав и работу публичной сборки. `tests/README.md` — краткие команды. Это отличается от `backend/tests/` и `demo/tests/`.

В `docs/` лежат главы 01–26, оглавление 00 и отдельный промпт для подготовки фотографий. Это исходники документации Markdown, которые не входят в публичную витрину.

## Что создаётся во время работы

| Артефакт | Можно пересоздать? | Что учитывать |
|---|---|---|
| `.public/`, `demo/.public/` и маркеры сборщика | Да, из исходников | Ручные изменения исчезнут при сборке |
| `.venv/`, `__pycache__/`, `.pytest_cache/` | Да | Не являются данными магазина |
| `backend/dev.db` | Только с потерей локальных записей | Локальные аккаунты, каталог и заказы |
| `backend/dev-mail.log` | Новые письма создадут файл | Содержит коды локального режима |
| `backend/media/` или Docker volume `media` | Нет, нужны оригиналы/копии | Загруженные фотографии |
| Docker volume `pgdata` | Нет, нужна копия базы | Рабочие записи магазина |
| `deploy/backups/` | Это сами резервные данные | Хранить также вне сервера |
| `deploy/.env`, сертификаты | Нужны защищённая копия/перевыпуск | Не публиковать и не коммитить |

## Как проследить функцию от кнопки до базы

Для заказа: `pages/checkout.html` → `js/pages/checkout.js` → `js/store/remote.js` → `schemas/orders.py` → `api/routers/orders.py` → `services/payments/` и `db/models.py` → `api/serializers.py` → ответ интерфейсу. Если API выключен, используется локальная реализация `js/store/orders.js`.
